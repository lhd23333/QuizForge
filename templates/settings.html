MinerU API Token

用于 PDF/图片 OCR 识别，在 mineru.net 的「API 管理」页创建（付费服务）。

这里填了就优先用这份；一份都没填则回落到 vendor/project_alpha/.env 里的 MINERU_API_TOKEN。 两处都没有时，AI 识别会报错，其余功能（手动导入、题库管理、组卷导出）不受影响。

可以添加多份：每次真实 OCR 请求会按当前忙闲挑 最空闲的一份；题干和解析也能分别取凭证。多 Token 主要用于独立账号负载、失效 切换和可用性，同一账号的 Token 通常共享官方频控与优先级额度。

密钥存储

MinerU、Doc2X 与 LLM 的 API Key 都用 Fernet 对称加密后存在 data/ 下（data/mineru.json / data/doc2x.json / data/providers.json），加密密钥是 data/.enc_key。

删掉或换掉 data/.enc_key，已存的所有密钥都会 永久解不开，只能回这一页重新填。这个文件已在 .gitignore 里， 不要提交到 git，也不要加进任何备份/同步工具。

本应用只监听 127.0.0.1、没有任何用户认证， 请勿改成对局域网或公网监听。

识别模型（LLM）

OCR 识别出的内容可交给大模型整理成题目。不配这里也能用——会走 内置默认 DeepSeek（读 vendor/project_alpha/.env，老行为），但那条路的 max_tokens 写死 8192，换推理模型会因思维链占满预算而「返回空内容」。 支持任意 OpenAI 兼容接口（DeepSeek / 阿里云百炼 / 硅基流动 / 中转站 / 自建等）。 可以存多套，在列表里点「启用」随时切换。

模型分两条路径用，各自独立启用：

  • 导入识别：把 OCR 结果整理成题目，要的是长上下文的 文本模型。
  • 配图重绘：把题目里的照片重画成矢量图（TikZ）， 必须支持图片输入——纯文本模型（如 deepseek-chat、 deepseek-v4-pro）会直接报错。没单独配时会回落到「导入识别」那套， 方便先试一下。

一套凭据可以同时服务两条路径（两个开关都点亮），也可以各配一套。

Base URL：填 API 根地址即可，会自动补全 /v1， 也不用管 /chat/completions 后缀——中转站直接填域名（如 https://yapi.click）就行，和 CC Switch 里的写法一致。 也可以填本机推理服务的回环地址（如 http://127.0.0.1:11434/v1）。

max_tokens：推理模型（如 deepseek-v4-pro）的思维链和正文共用这份预算， 填小了会思维链占满、正文一个字都不吐，建议 32000 以上；非推理模型（如 deepseek-chat）8192 够用。
