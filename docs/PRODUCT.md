# QuizForge 软件版产品全景

本文描述 QuizForge 软件版长期稳定的产品结构、各板块核心原则和开源演进边界。具体版本变化见 [`../CHANGELOG.md`](../CHANGELOG.md)，使用与安装入口见 [`../README.md`](../README.md)，早期迁移技术记录见 [`../迁移说明.md`](../迁移说明.md)。

## 产品定位与总原则

QuizForge 是面向教师和个人题库维护者的 Windows 本地题库与组卷工具，覆盖“试卷识别—校对入库—本地管理—讲义编排—试卷导出”，并提供可选的 Agent 工作区把这些能力编排成自然语言工作流。题目以普通 Markdown 保存在用户选择的题库目录，可与 Obsidian 共用；桌面程序只监听本机，不把无鉴权服务暴露到局域网或公网。软件按 `GPL-3.0-or-later` 开源，核心功能不需要账号、额度、设备授权或云端任务；服务器只提供可选更新清单。

所有板块共同遵循五项原则：用户数据优先且可直接访问；自动化不能用猜测掩盖歧义；第三方 OCR/LLM 调用必须由用户主动触发并使用用户自己的凭据；页面预览、题库数据和导出结果尽量共用同一结构规则；升级只覆盖程序文件，不破坏题库、凭据、任务和旧兼容文件。

成熟度使用三档：**稳定**表示已进入日常使用并有明确回归边界；**可用**表示核心闭环成立，但仍有已知发布或体验限制；**试验**表示能力可验证但尚不承诺长期接口。

## 1. 桌面工作区

- **产品定位**：承载独立 Windows 桌面窗口、栏目导航、多题库切换和本地 Flask 服务，让用户无需 Python 或 Obsidian 即可使用主要功能。
- **用户价值**：题库、导入、任务、讲义、资料库和设置集中在一个常驻工作区；切换栏目时已打开资料和分栏状态不会被销毁。
- **核心原则**：桌面壳只负责本机进程、窗口和题库上下文，业务规则仍留在既有 Web 应用；全局导航固定在左侧，功能页只保留操作所需文字，较长说明统一放入按页面切换的帮助抽屉；窗口无边框交互不得牺牲最小尺寸、缩放和关闭语义；浏览器及 Obsidian 模式继续兼容。
- **关键边界**：后端只监听 `127.0.0.1` 随机端口，所有写请求携带进程随机令牌；题库登记和窗口配置保存在本机 `desktop.json`；断开的题库只能标记不可用，不能擅自移动或删除磁盘内容。
- **当前成熟度**：**稳定**。独立桌面运行、多窗口题库上下文、无边框缩放、健康检查和日常目录版覆盖均已有验证链路。

- **Agent 工作区**：右侧面板可与题库主区域并排打开，采用无头像的开放式助手正文和克制的用户消息，支持安全 Markdown／KaTeX、流式回复、工具状态、真正停止、多会话与可拖动布局。Chat Completions 和 Responses API 共用固定 SSE 事件协议；只有完整成功终态且参数通过 JSON 校验的工具调用才执行，取消、断流和半成品调用不得产生副作用。标准模式下，本机命令、题库写入、付费转换和模板操作逐次审批；危险模式必须在当前会话明确确认警告后临时开启，可免确认执行具有当前 Windows 用户权限的 PowerShell、CMD、Python 等本机命令及受控操作，切换会话或应用重启即失效。危险授权只跳过人工审批，不绕过路径、参数、ZIP、模板、CSRF、任务锁和审计硬校验。Agent Provider、Skill 与偏好使用独立本机存储，当前成熟度为**可用**。

## 2. 题库管理

- **产品定位**：以“一个题目一个 Markdown、文件夹即分类目录”的方式管理数学和物理题库。
- **用户价值**：用户可在 QuizForge 与 Obsidian 之间自由查看或编辑题目，不被私有数据库锁定；支持筛选、结构化搜索、标签、难度、星标、可搜索的内部备注、拖放排序／移动／复制、原地编辑、单题 TeX ZIP、查重和回收站。解析和备注在编辑时按内容折叠并独立控制当前预览，长内容在限定高度内滚动。
- **核心原则**：题目身份取 frontmatter 的 `id`，不依赖文件名；目录树反映真实磁盘结构，并严格区分“子节点已加载”和“当前已展开”，手动展开状态只在当前题库窗口会话内保存；搜索始终与当前文件夹及已启用筛选取交集，并覆盖分页前的完整逻辑集合；题卡重排只在未筛选的真实叶子题集中开放，并按相邻锚点落盘，不能用已加载前缀重写完整题序；页面局部操作只更新当前题卡或目录节点，服务端勾选状态必须在局部替换和无限滚动后恢复；软删除优先，恢复能力优先于主动清理。
- **关键边界**：所有路径必须解析后确认仍位于题库根目录；保留目录、符号链接逃逸和自身／后代目录移动必须拒绝；外部 Obsidian 修改以 mtime 和原始字节保护，不能静默覆盖；所有落盘文本统一为 LF。
- **当前成熟度**：**稳定**。核心 CRUD、惰性目录树、无限滚动、批量操作和软删除已进入日常使用；大题库性能继续按真实数据回归。

## 3. 资料库与讲义

- **产品定位**：资料库负责在工作区中阅读和安全编辑题库文件及识别历史中的 Markdown、PDF 与图片，为 DOC／DOCX 建立待转换索引，并提供 PDF 页面处理和面向题库的自然制卡入口；讲义负责把题目和自由文本编排成可导出的教学材料。
- **用户价值**：备课时无需离开软件即可对照原卷、识别 Markdown、笔记与题库；资料文件夹可在软件内创建、重命名、移动或复制，PDF 可提取、排序、旋转、拆分和合并，DOCX 可按需转成 Markdown／PDF。Markdown 选区或粘贴文本、PDF 指定页面或当前阅读画面框选、现有图片都能送入单题／多题制卡；PDF／图片默认只做 OCR 与机械拆题，需要时再显式开启大模型规范化。题卡可命名并由后台任务写入所选已有题集；讲义继续支持 A4 单栏、A4 双栏和 16:9 页面。
- **核心原则**：资料标签和桌面版 WebView2 PDF 阅读器常驻，栏目切换只隐藏不销毁；Markdown 保存必须做外部修改冲突检测；文件改名或移动原位重映射已打开标签和草稿，普通拖动为移动、Shift 拖动才复制，拖回标题栏或树空白处回到根目录，同目录文件树始终按名称排序。PDF、DOCX 与制卡统一登记为可持久化的资料库后台任务，失败或重启后中断只允许用户明确重试；讲义 Markdown 是唯一真源，自动分页和预览 SVG 不写回用户文档。
- **关键边界**：普通资料只访问题库根目录内的可见白名单文件；识别历史经保留虚拟路径访问当前题库独立状态目录，不能越界到其他题库或回收站。`_assets`、`_handouts`、`_backups` 及其内容不进入通用文件操作；文件改名不能改变扩展名，移动与复制不得覆盖同名目标或把文件夹放入自身后代，复制题卡 Markdown 必须生成新 ID。PDF 和图片只读；DOCX 只索引并在用户选择后转换，旧 DOC 需先另存为 DOCX。PDF 工具只处理资料库相对路径，不提供任意磁盘文件选择器；产物默认在源文件夹使用带“提取／排序／旋转／合并／第x-y页”的名称，也可接受资料库内已存在目录的相对输出位置。Markdown 保存统一做 mtime 冲突校验；制卡图片只接受 PNG／JPG／WEBP／BMP，保存位置只能选择已有题集且默认“临时卡片”，大模型规范化默认关闭。单题模式拒绝多题结果，智能模式检查题号断档和重复，白名单模式允许跳号但仍经过既有质量闸门。PDF 原位框选截取用户当前可见且未被其它窗口遮挡的画面，清晰度随屏幕缩放变化，不记录精确页码或 PDF 坐标，且仅支持 Windows 桌面版；浏览器和 Obsidian 模式仍可使用按页识别。讲义删除只作用于明确选择的讲义文件，不能波及题目或资产。
- **当前成熟度**：**可用**。资料浏览、文件管理、PDF／DOCX 工具、自然制卡、多标签、双分栏、Markdown 编辑和讲义导出闭环已完成；复杂文档转换、长讲义和更多教学模板仍需持续实用验证。

## 4. 试卷识别与导入

- **产品定位**：将 PDF、Word 或图片经过 MinerU／Doc2X OCR、机械切块和可选 LLM 规范化，转换为可审核、可追溯的题目。
- **用户价值**：支持单卷、批量题干答案配对和多试卷合集，减少人工录题，同时允许在任何歧义处停下来校对。
- **核心原则**：OCR 后端、拆题方式与题号边界策略彼此正交；机械切块先固定题数，LLM 不能随意增减。智能边界继续检查题号连续性；强制白名单只把明确题号写法视为边界，跳号、乱序和重复号保持原序，但仍经过选项、乱码、孤儿解析、图片和内容守恒质量闸门。有歧义时保留原始材料并提示人工处理，不按语义或页序猜配。
  - **人工恢复**：合集结构无法可靠拆分时保留已完成的 OCR 缓存，允许用户对照原文件直接修订 Markdown，再按整份或多组结构重试；恢复流程不得重复调用付费 OCR。
  - **识别历史**：每次新识别尝试先归档原文件，成功后原子补入最终 Markdown；重转产生新记录，不覆盖旧结果。历史删除先进入独立回收站，只有用户明确永久删除才释放文件；归档 Markdown 再次提取只建立待审核任务，不调用 OCR 或 LLM。
  - **提示词与交换格式**：内置只读提示词帮助用户把 PDF／图片题目转换为 QuizForge Markdown，或把 PDF／TeX 样式转换为候选 TeX 模板；本地自定义提示词独立原子存储。Markdown 可直接粘贴，带图材料可使用包含 `quizforge-import.json`、`questions.md` 和 `assets/` 的 `.qfimport.zip`／`.zip`，也可在逐题校对卡粘贴原图。包导入必须验证路径、符号链接、文件类型、重复项、缺图、压缩规模和内容摘要，失败时回滚本轮新资产，确认校对后才正式入库。
  - **关键边界**：第三方调用只由用户主动发起；凭据不写入任务快照、历史清单、语料或日志；同组输入类型不合法、图片损坏、合集结构冲突或模型删图时整组失败或转人工校对。无书签合集依赖连续题号展开，拒绝强制白名单；多图片白名单任务只有在同轮 MinerU 页码和 Markdown 锚点完整、唯一且单调时才隔离页面，Doc2X 或证据不足时保留全文并阻断免审。任务重启后不自动重放在途请求，完成结果可继续审核。识别历史按题库隔离，不自动过期，也不写入用户题库目录。
- **当前成熟度**：**稳定**。单卷、批量、合集、续传、质量检查和稳定刷新已有大量离线回归与真实试卷验证；新 OCR 版式仍须以真实样本保守扩展。

## 5. 图片资产

- **产品定位**：为全部登记题库提供统一、可复用且可安全清理的共享图片目录。
- **用户价值**：题目图片能在 QuizForge 与 Obsidian 中共同显示，多次识别不会重复制造相同文件，切换题库也不丢图。
- **核心原则**：`desktop.json.assets_dir` 是桌面端唯一图片目录；同内容复用、同名异内容拒绝覆盖；题目软删除保留图片；永久清理必须跨全部登记题库、回收站、讲义和安全备份确认无引用。
- **关键边界**：任一题库不可访问或 Markdown 读取失败时，清理操作 fail-closed；删除前后二次扫描，只删除两次均无引用且期间大小、mtime 未变化的普通图片；切换共享目录只做无损复制，不删除来源。
- **当前成熟度**：**稳定**。共享寻址、迁移预检、内容摘要复用和孤儿体检已有实现；用户仍需显式选择正确的公共 `_assets` 目录。

## 6. 组卷导出

- **产品定位**：把题库选择结果转换为 PDF、可编辑 DOCX、TeX 和含资源的 ZIP，并把讲义转换为 PDF／TeX／便携 Markdown，覆盖普通试卷、标准试卷、双栏刷题和 16:9 课堂课件。
  - **用户价值**：PDF 提供最终印刷权威版，DOCX 提供可继续修改的公式、表格、图片、题号、解析和页眉页脚，TeX ZIP 可交给 Overleaf 编译；没有本机 TeX 时可使用 HTML/KaTeX 近似预览。
- **核心原则**：PDF 与 DOCX 共用题目选择和内容意图，但版式实现独立演进；PDF 追求稳定印刷，DOCX 追求语义完整和可编辑，不做 PDF／TeX 反向转换；图片组不可被分页或分栏逻辑随意拆散；用户公式和自定义分区不做静默清洗。
  - **自定义模板**：可执行模板使用 schema v2 目录登记，只接受 UTF-8 `.tex` 或带根清单的 `.tex.zip`；PDF 只能作为只读版式参考。模板必须保留运行时宏且仅含一个 `$body$`，按声明的导出模式用固定中文、公式、表格、图片和解析样例真实编译，验证结果绑定源码哈希；只有模式兼容、哈希未变化并经用户确认的模板才进入导出选择，未指定时继续使用内置模板。
  - **关键边界**：每次导出使用独占工作目录，限制并发避免资源争用；DOCX 通过参数数组调用随包 Pandoc，并在返回前校验 ZIP、XML、关系和媒体完整性；Word／WPS 可自然重排，底色与 WIMath 标志仅用于 PDF／TeX，独立讲义工作区暂不导出 DOCX；TikZ 编译禁止 shell escape 和危险输入输出；MiKTeX 一键安装必须同时通过固定官方 HTTPS、长度、SHA-256 和 Authenticode 校验，上游安装器未签名时入口保持关闭；失败要返回明确原因，不暴露残缺成品。
- **当前成熟度**：**稳定**。主要 PDF 版式和 Word 语义路径已有自动化与 Microsoft Word 真实产物回归；跨机器字体、WPS、MiKTeX 状态和极端长题仍是发布验收重点。

## 7. 本地凭据与可选更新

  - **产品定位**：设置页维护 MinerU、Doc2X 和 OpenAI 兼容 LLM 的本地凭据，并提供本机 TeX、Overleaf ZIP 和外观配置。
  - **用户价值**：无需注册、登录或激活即可使用题库、导入、预览和导出；多份 OCR Key 可按忙闲和轮转使用。
  - **核心原则**：所有 API Key 使用本机 Fernet 加密，明文只在调用期间存在；更新检查只发送版本和平台信息，不上传题库、正文、路径或凭据。
  - **关键边界**：软件后端只监听 `127.0.0.1`；更新清单必须是 HTTPS 且经过结构校验，安装包必须通过 SHA-256 与 Authenticode 证书指纹校验，只有用户确认后才下载和覆盖。
  - **当前成熟度**：**可用**。本地配置和导出路径已实现，联网检查、下载、校验、静默覆盖与重启链路已接入；正式自动安装仍需服务器发布经过签名的 Windows 安装包。

## 8. 发行与赞助

  - **产品定位**：GPL 开源免费软件，通过可选赞助入口支持持续开发，服务器只承担更新清单，安装包也可从 GitHub Releases 手动下载。
  - **用户价值**：所有人都可以下载安装和使用，不因账号状态影响本地题库访问、编辑或导出。
  - **核心原则**：日常修改通过 `DirectBundle` 更新本机安装版，正式 Setup 只在明确发布时构建；更新资源必须走 HTTPS、哈希和签名校验。
  - **关键边界**：不把旧账号、授权、额度或云任务重新接回新运行路径；旧兼容文件只保留，不作为授权或 Doc2X 调用来源。公开二进制发行必须同时满足 GPL 对相应源代码的提供要求。
  - **当前成熟度**：**可用**。开源本地模式已成为默认运行模式，赞助地址保留配置孔位，正式公开安装包和更新清单仍待发布。

## 9. 视觉与交互基线

- **产品定位**：为桌面壳、浏览器和 Obsidian 嵌入页提供同一套克制的工作台视觉，不把页面做成营销式或装饰性卡片界面。
- **核心原则**：新用户默认使用柔和石墨深色；画布和面板使用中性灰层级，WIMath 蓝只用于交互状态、链接和品牌区；旧用户已保存的主题和强调色不被覆盖。各页遵循“主流程常驻、高级设置折叠”，宽屏形成稳定工具栏和工作区，窄屏转为单列。单选下拉采用渐进增强的圆角 listbox，但原生 `select` 始终是表单值源并在脚本失败时回退；通用命令优先使用 16–18px 线性图标、明确 tooltip 和稳定尺寸。
- **图标边界**：QuizForge 产品图标用于应用识别、favicon、标题栏和关于页；WIMath mark 与联名图形只用于品牌署名；文件夹、设置、导入等功能使用统一的线性 `icon()` 宏，不使用 Unicode 字符或缩小的品牌图形。
- **实现与维护**：应用自有 CSS 只有 [`../static/style.css`](../static/style.css)，新增规则按 `tokens`、`base`、`controls`、`shell`、`settings`、`workspace`、`overlays`、`compat` 分层；随包 KaTeX 供应商样式保持独立，不纳入应用令牌。受控品牌文件及构建校验见 [`BRAND_ASSETS.md`](BRAND_ASSETS.md)，完整 CSS 令牌、响应式和无障碍要求见 [`CSS_STYLE_GUIDE.md`](CSS_STYLE_GUIDE.md)。
- **当前成熟度**：**可用**。首期令牌、桌面外壳、导航、设置和主要工作区已建立基线；历史 `legacy` 规则仍在分批迁移，新增功能必须先遵守规范，不以旧样式作为范例。
