# QuizForge CSS 技术约定

本文是 QuizForge 软件版的 CSS 单一约定，面向后续功能开发和视觉回归。首期重构以 Windows 桌面壳为优先，同时保证浏览器和 Obsidian iframe 继续复用同一套页面。实现入口是 [`../static/style.css`](../static/style.css)；不要再为单个页面建立第二份全局样式表。

本文记录的是稳定规则，不把某个页面的临时修补写成组件 API。若现有页面尚未迁移到新规则，应在对应改动中逐步迁移，并保留原有 DOM、路由和数据语义。

## 1. 视觉基线

- 工作区采用安静、克制、可长时间阅读的黑灰层级。新用户的默认主题是柔和石墨深色，不使用接近纯黑的背景；旧用户已经保存的主题和强调色不被覆盖。
- 画布使用中性灰，面板使用相邻的灰阶区分层级。WIMath 蓝只用于交互状态、链接和品牌区，不作为大面积页面背景。
- 圆角、阴影和边框都应服务于层级，不做装饰性卡片堆叠；页面区块不嵌套卡片，只有重复条目、弹窗和确实需要框定的工具可以使用卡片。
- 设置页和工作区优先采用“标题 + 说明 + 控件”的行式布局，控件列靠右或保持稳定宽度，避免把多个设置拼成无边界的表单块。
- 不改变题目正文、导出模板或业务数据的语义来追求视觉效果。视觉规则只约束容器、控件、间距、颜色和图标。

## 2. 样式分层

`static/style.css` 的层声明顺序是固定的：

```css
@layer legacy, tokens, base, controls, shell, settings, workspace, overlays, compat;
```

源码块按 `tokens` 到 `compat`、再到 `legacy` 的物理顺序排列。顶部声明刻意把
`legacy` 放在最低级联优先级，因此历史兼容规则不会反压新设计；新增规则不得
写入 `legacy` 区，也不得为了改变视觉层级调整这条声明顺序。

各层职责如下：

| 层 | 职责 | 新代码要求 |
| --- | --- | --- |
| `legacy` | 旧页面和历史嵌入场景的兼容底座 | 只修复兼容问题，不新增设计规则 |
| `tokens` | 颜色、间距、圆角、阴影和尺寸令牌 | 新值先定义语义令牌，再提供旧变量映射 |
| `base` | 重置、字体、正文、焦点和通用可见性 | 不写页面业务选择器 |
| `controls` | 输入框、按钮、图标按钮、状态提示 | 通过变体类表达语义，不靠选择器顺序碰运气 |
| `shell` | 标题栏、全局导航、主工作区和通用面板 | 保持桌面壳与普通页面的尺寸契约 |
| `settings` | 设置导航、设置组、设置行和模型表单 | 复用行式设置结构，不在模板写大量内联样式 |
| `workspace` | 题库、资料库、讲义、Agent 等业务工作区 | 只处理布局和状态外观，业务状态由现有类名表达 |
| `overlays` | `dialog`、菜单、抽屉和遮罩 | 明确层级、焦点和窄屏行为 |
| `compat` | `embedded-view`、桌面宿主和响应式退化 | 只做宿主差异和断点覆盖 |

新增规则必须放在与职责相符的层中。不要通过重复选择器、末尾覆盖或无理由的 `!important` 解决层级问题；确有宿主兼容需要时，应在 `compat` 层留下原因。

## 3. 令牌

以下是当前基线令牌，定义在 `@layer tokens`。业务 CSS 应优先使用这些令牌，不直接写颜色和阴影。

### 中性色和强调色

| 令牌 | 深色默认值 | 浅色值 | 用途 |
| --- | --- | --- | --- |
| `--qf-canvas` | `#202124` | `#f5f6f8` | 页面画布 |
| `--qf-panel` | `#292a2d` | `#ffffff` | 面板、导航、主容器 |
| `--qf-elevated` | `#323338` | `#f0f1f3` | 输入框、工具条、悬浮层内层 |
| `--qf-border` | `#3b3d43` | `#e1e3e7` | 普通分隔线 |
| `--qf-border-strong` | `#4a4d55` | `#cbd0d8` | 输入框和需要强调的边框 |
| `--qf-text` | `#f1f3f4` | `#202124` | 主文字 |
| `--qf-text-secondary` | `#c5c8cf` | `#5f6368` | 次级文字 |
| `--qf-text-muted` | `#9297a1` | `#656b75` | 辅助说明、占位和标签 |
| `--qf-accent` | `#63b3ff` | `#2457d6` | 链接、选中、焦点和主要操作 |
| `--qf-accent-text` | 按背景派生 | 按背景派生 | 链接和文字图标；自定义色不足 AA 时向黑/白调整 |
| `--qf-accent-hover` | `#4fa3ed` | `#1c46b2` | 强调色悬停（现代 WebView2 按当前色混合） |
| `--qf-on-accent` | `#101214` | `#ffffff` | 主要按钮文字；自定义色按对比度动态选择 |
| `--qf-accent-soft` | `rgba(99,179,255,.14)` | `rgba(36,87,214,.10)` | 选中和提示背景 |
| `--qf-accent-ring` | `rgba(99,179,255,.32)` | `rgba(36,87,214,.24)` | 键盘焦点环 |

成功、危险、警告和信息状态分别使用 `--qf-success`、`--qf-danger`、`--qf-warning`、`--qf-info` 及对应的 `*-soft` 令牌；填充状态的文字使用 `--qf-on-success`、`--qf-on-danger`、`--qf-on-warning`、`--qf-on-info`。状态色只表达状态，不作为品牌色或大面积装饰。

### WebView2 兼容基线

独立桌面版依赖系统 WebView2。完整的层叠层、`:has()`、`dvh` 和 `color-mix()` 体验分别以 Chromium/Edge 99、105、108 和 111 及以上为基线；部署环境应优先使用 Evergreen WebView2。关键背景、边框和焦点令牌必须先写静态 CSS 值，再在 `@supports` 或后置声明中启用现代语法，不能依赖 `var(--token, fallback)` 兜底，因为变量本身已定义但包含未知函数时不会触发 `var()` 的回退参数。若未来必须支持 Edge 99 以下版本，需要提供不使用 `@layer` 的独立基础样式，不要把旧浏览器兼容逻辑混入本层设计规则。

### 尺寸和层级

| 令牌 | 值 | 约定 |
| --- | --- | --- |
| `--qf-radius-sm` / `--qf-radius-md` / `--qf-radius-lg` | `6px` / `8px` / `12px` | 控件、面板、弹窗依次使用 |
| `--qf-control-height` | `34px` | 标准按钮和单行输入 |
| `--qf-space-1` 至 `--qf-space-6` | `4/8/12/16/24/32px` | 所有布局间距优先从刻度选择 |
| `--qf-shadow-1` 至 `--qf-shadow-3` | 低到高三档 | 普通面板、悬浮层、模态层 |
| `--qf-nav-width` | `216px` | 桌面全局导航基线，可由用户拖动调整 |

旧页面仍使用的 `--bg`、`--surface`、`--text`、`--primary`、`--sp-*` 等变量必须继续保留，但只能在令牌层映射到 `--qf-*`，不要在业务选择器重新定义一套颜色。

主题由 `<html data-theme="dark|light">` 控制。用户在外观设置中选择的强调色可以覆盖 `--primary`，但仍须满足文字对比度，并且不能把强调色扩散为画布或面板底色。偏好文件仍只有原有三个字段；等于当前模式默认色的值按默认处理，只有其它合法颜色才注入自定义覆盖。原始色用于填充和边框，链接/文字图标通过 `--qf-accent-text` 自动派生到中性背景上的至少 4.5:1；这不会改写用户保存的色值。

## 4. 字体和文字

- 使用系统字体栈：`-apple-system, BlinkMacSystemFont, "Segoe UI", "Microsoft YaHei", sans-serif`。不在 CSS 中下载字体，也不依赖 CDN。
- 基准字号为 `13px`，正文行高约 `1.5`；页面标题、分组标题和说明分别使用现有 `h1`、`h2`、`h3` 层级，不在紧凑工具栏使用英雄式大标题。
- `letter-spacing` 固定为 `0`，禁止按视口缩放字号或使用负字距。长中文标签应换行或让容器伸缩，不能溢出按钮和卡片。
- 颜色表达层级：主文字使用 `--qf-text`，解释和元数据使用 `--qf-text-secondary`，低优先级说明使用 `--qf-text-muted`。不要仅靠颜色传达成功、失败或选中状态。

## 5. 控件和状态

### 类名和颜色约定

- 类名使用小写 kebab-case，并按“组件-部件-状态”组织，例如
  `.settings-row-control`、`.agent-session-item`、`.is-active`；同一组件的
  状态优先使用 `.is-*` 或已有 `data-*` 状态，不通过第几个子元素或源码顺序
  猜测状态。通用组件类（`.btn`、`.input`、`.panel`、`.card`、`.ui-icon`）
  不得带业务名词或页面专属变体。
- 模板中禁止新增 `style="..."`，也不要在脚本中给元素写视觉属性来绕过 CSS。
  动态宽度、进度和壁纸等确实由数据决定的值，使用已有的 CSS 自定义属性、
  `data-*` 属性或专用状态类，并在对应模块的样式层集中定义。
- 业务样式禁止硬编码颜色、阴影和间距。颜色必须引用 `--qf-*` 语义令牌；
  只有令牌定义、品牌资产镜像、打印/第三方内容隔离和明确的浏览器回退可以
  直接写颜色，并应在同一处注明原因。不要在页面末尾追加一组覆盖规则来修正
  前面的颜色；需要宿主差异时放入 `compat` 层。

### 通用控件

- `.input`、裸 `input/select/textarea` 共享 `34px` 最小高度、`6px` 圆角、`--qf-elevated` 背景和 `--qf-border-strong` 边框。
- `.btn` 是文字操作的基础类；`.btn-primary` 表示当前上下文唯一的主要动作，`.btn-ghost` 表示低强调动作，`.btn-danger` 只用于明确的破坏性动作，`.btn-sm` 只在密集工具栏使用。
- 图标动作使用 `.icon-btn` 或对应组件的图标按钮类，固定至少 `30 × 30px` 命中区。若熟悉图标足以表达含义，不要再包一层圆角文字胶囊。
- `:hover` 只改变一档背景、边框或文字颜色；`:active` 的位移不超过 `1px`。`:focus-visible` 必须保留 `2px` 强调色外框和可辨识的偏移。
- 禁用控件统一降低不透明度并禁止指针操作；不能只用灰色而没有 `disabled` 或 `aria-disabled` 语义。

### 设置行

设置页稳定使用以下 DOM 契约，JS 依赖的 `data-settings-*` 属性和字段 ID 不得删除：

```html
<section class="settings-section">
  <h2>分组标题</h2>
  <p class="settings-note">简短说明。</p>
  <div class="settings-row">
    <div class="settings-row-copy">
      <label for="setting-id">设置名称</label>
      <small>该设置的影响范围。</small>
    </div>
    <div class="settings-row-control">
      <input id="setting-id" class="input">
    </div>
  </div>
</section>
```

每一行只放一个清晰的设置意图；复杂表单可在行下使用 `.settings-form-grid`，模型表格、令牌列表等重复数据保持独立滚动容器。不要把说明、输入和操作按钮用随机 margin 拼成一行。

## 6. 布局和响应式

- 桌面标题栏固定 `40px`；左侧全局导航基线 `216px`，主内容使用有界 `.app-page`，避免在超宽屏无限拉伸。
- 设置页基线为 `168px` 导航列 + 内容列；分组是独立的中性面板，设置行用水平分隔线建立节奏。
- `html.embedded-view` 下隐藏桌面标题栏和全局导航重复层，主页面恢复 `100%` 宽度；不要通过 JS 复制一套嵌入专用页面。
- `900px` 以下设置导航退化为可横向滚动的选项条；`680px` 以下主导航隐藏、主内容占满宽度、表单改单列；`480px` 以下抽屉和会话列表使用覆盖层。新增断点必须说明要保护的最小内容宽度。
- 侧栏、分栏和 Agent 面板的可拖动宽度由现有 `data-split-*` 契约控制，CSS 只提供最小/最大约束和视觉反馈，不在页面脚本中硬编码另一套尺寸。

## 7. 图标约定

- 运行时功能图标唯一入口是 [`templates/_icons.html`](../templates/_icons.html) 的 `icon()` 宏。新增图标先补宏，再在模板中调用；不要在模板或 JS 里散落手写 SVG。需要在客户端动态创建节点时，使用基础模板暴露的 `window.QFIcon(name, className)`，不要复制 SVG path。
- 功能图标采用 `24 × 24` viewBox、`fill="none"`、`stroke="currentColor"`、圆角线帽/连接和约 `1.75` 的线宽，尺寸通过 `.ui-icon` 或组件类控制。
- 禁止新增 Unicode 字符代替交互图标（例如 `★`、`✎`、`×`、`⇄`、`⋯`）。需要的语义应加入 `star`、`edit`、`x`（关闭）、`move`、`more-horizontal` 等明确名称，并保持可替换。当前高频动作还包括 `plus`、`minus`、`download`、`scissors`、`arrow-up`、`arrow-down`、`arrow-left-right`、`arrow-up-down`、`chevron-*`、`undo-2`、`redo-2`、`list`、`list-ordered`、`quote`、`layout-columns`、`layout-rows` 和 `square`。历史模板中的符号只在迁移完成前保留，不得复制到新功能。
- 图标按钮必须有 `title` 或可读的 `aria-label`；装饰图标加 `aria-hidden="true"`。图标颜色继承文字层级，选中状态才使用 `--qf-accent`。
- WIMath 标志和 QuizForge 产品图标属于品牌资产，不能缩小后充当文件夹、设置或删除等功能图标，详见 [`BRAND_ASSETS.md`](BRAND_ASSETS.md)。

## 8. 可访问性和动效

- 键盘焦点、错误、成功和选中状态必须同时有结构或文字提示；颜色对比度按 WCAG AA 作为最低目标。
- 可点击元素使用真实的 `<button>`、`<a>`、表单控件和正确的 `type`，不要用可点击 `<span>` 模拟按钮。
- 动效只用于状态过渡和抽屉开合，默认短于 `200ms`；`prefers-reduced-motion: reduce` 下关闭或缩短过渡。不得用闪烁、缩放或大范围位移传达重要信息。
- 弹窗、菜单和抽屉必须保留 Esc 关闭、焦点回收和遮罩层级；桌面无边框窗口的拖动区不能覆盖交互控件。

## 9. 新功能提交检查

提交新的页面或组件前，逐项确认：

1. 是否复用了现有 `--qf-*` 令牌和组件类，而不是新增同义颜色、间距或圆角？
2. 规则是否放在正确的 `@layer`，并且没有依赖文件末尾覆盖或无理由的 `!important`？
3. 页面在桌面、嵌入 iframe、窄屏和深浅主题下是否仍有稳定尺寸，文字和控件有没有溢出或重叠？
4. 交互是否使用真实控件、键盘焦点和 `aria` 语义，图标是否来自 `icon()` 宏？
5. 是否完成设置页五个分类、主工作区和至少一个窄屏视口的手动截图/交互验收？
6. 用户可感知的视觉或交互变化是否已写入 [`../CHANGELOG.md`](../CHANGELOG.md)，长期原则是否同步 [`PRODUCT.md`](PRODUCT.md)？

现有 `legacy` 规则的迁移可以分批进行；在迁移完成前，新增代码仍必须遵守本文，不能以历史样式作为新功能的范例。
