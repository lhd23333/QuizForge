追加式变更记录：记录每次涉及 `vendor/project_alpha` 重新同步、依赖关系、
发布流程等"架构性"改动的原因与做法。这是变更记录，不是使用文档——日常

## 2026-08-07：project-alpha 内置化 与 GitHub 首次发布

把 `project-alpha`（PDF/图片 → MinerU OCR → DeepSeek 规范化的转换库）整体
vendor 进本项目，使其成为完全自包含的系统，并打包发布到 GitHub。

### 1. 背景

改动前，`config.py` 里的 `PROJECT_ALPHA` 指向一个外部路径，本项目的
`converter.py` 依赖这个外部目录才能跑 AI 识别导入。这意味着换机器、或者
把本项目单独发布出去时，AI 导入功能会直接失效（外部路径不存在）。

目标：把 project-alpha 的必要代码整体拷进本项目内部（`vendor/` 目录），
让本项目成为一个不依赖任何外部同级目录的独立系统；同时保留"AI 导入需要
用户自己的 MinerU/DeepSeek 密钥，其余功能离线可用"的产品形态不变。

### 2. project-alpha 源的甄别

发现磁盘上同时存在两份 project-alpha：

- `_backups\20260717_014744_post-autonomy\project-alpha\`——**过期**快照。
- `D:\data\ai-coding\project-alpha\`——**当前活跃、最新**的版本。

直接对比 `src/pipeline.py::run_parse()` 与 `src/normalizer.py::normalize()`
的函数签名确认：只有后者带 `only_numbers: list[int] | None = None` 参数，
而本项目 `converter.py` 恰好会传这个参数。如果错拿了备份里的旧版本，
运行时会直接抛 `TypeError: unexpected keyword argument 'only_numbers'`。
因此最终从 `D:\data\ai-coding\project-alpha\` 拷贝，而不是备份目录。

### 3. vendor 了什么，排除了什么

拷进 `vendor/project_alpha/` 的文件：

```
vendor/project_alpha/
  .env.example
  src/
    __init__.py
    config.py
    deepseek_client.py
    exceptions.py
    mineru_client.py
    normalizer.py
    pipeline.py
    validator.py
  templates/
    normalize_prompt.md
```

**明确排除**（原样留在原 project-alpha 目录，不拷贝）：

- `main.py`——project-alpha 自己的 CLI 入口。本项目的 `converter.py` 是直接
  调用 `src.pipeline.run_parse()` 等库函数，从不走 CLI，所以不需要它。
- `.env`——**真实密钥**，绝不能进 git。只拷了 `.env.example`（安全模板）。
- `.claude/`、`.obsidian/`、`output/`、`__pycache__/`——project-alpha 自己的
  工具产物/配置，与本项目无关。
- `README.md`、`CLAUDE.md`、`AGENTS.md`、`移交说明.md`、
  `QuizForge使用手册.pdf`——project-alpha 自己的文档，本项目有自己的文档。
- `templates/exam_template.tex`——project-alpha 原版只有 791 字节，是个极简
  pandoc 模板；本项目自己的 `exam_template.tex`（5731 字节）已经演化出选择题
  排版、图片布局、页眉页脚等 QuizForge 专属宏，明显更完善，**保留本项目自己
  的版本，不覆盖**。

依赖方面：project-alpha 的 `requirements.txt` 提到 `pyyaml`，但 grep 了所有
vendor 进来的 `src/*.py`，没有任何文件 `import yaml`——确认这是历史遗留的
无效依赖，本项目 `requirements.txt` 未做改动（本项目用 `ruamel.yaml` 处理
自己的 frontmatter 需求，够用）。

## 2026-08-08：从服务器版（quizbank-web）移植识别/导出流水线

把服务器版 `quizbank-web` 里更新过的**流水线模块**整体移植进本项目，同时
保留本项目"一题一个 md 文件 + Obsidian 双链图片"的存储模型和 Obsidian 插件。

### 1. 背景与决策

服务器版 `quizbank-web` 是本项目的多用户 Web 分支，识别与导出流水线在那边
持续演进了很久。用户要求"完全同步"。

但两者**不是版本先后关系，而是两套不同的存储模型**：

- 本项目 `filestore.py`：一题一个 `.md`（YAML frontmatter + 正文），扫描
  目录即得题库，题库根目录就是 Obsidian vault，图片用 `![[文件名]]` 双链。
- 服务器版 `db.py`：SQLite（123KB），有 `owner_id`、多用户共享/邀请机制，
  图片走 `![alt](/qimages/<scope>/<file>)` + `IMAGES_DIR/<scope>/` 子目录。

字面意义的"完全同步"（把服务器版整个覆盖过来）会把 `filestore.py` 换成
`db.py`，也就直接摧毁 Obsidian 插件的立足点——插件的全部意义在于"题目就是
vault 里的普通 md 笔记，点一下在旁边的窗格里打开"。题进了 SQLite 就没有 md
可点了。

因此向用户列出了三个方案，用户选择 **A：只移植流水线模块，存储模型和插件
不动**。

### 2. 移植前的对比结论（决定成本的关键）

逐个模块比对函数清单后确认：**服务器版的每个流水线模块都是本项目对应模块的
严格函数超集**，没有一个函数被删掉或改签名——

| 模块 | 本项目 → 服务器版（公开函数数） |
| --- | --- |
| `dedup.py` | 4 → 4 |
| `mechfix.py` | 8 → 19 |
| `blocknorm.py` | 7 → 9 |
| `blocksplit.py` | 15 → 20 |
| `importer.py` | 11 → 19 |
| `llm_client.py` | 7 → 11 |
| `optcheck.py` | 新增（3） |
| `qualcheck.py` | 新增（10） |

另外确认：`exporter.export()` / `build_markdown()` 签名两边一致；**没有任何
流水线模块 import `db`**（多用户逻辑都在路由层，没有渗进流水线）；上游
`vendor/project_alpha` 两边零漂移，不需要重新 vendor。

`exam_template.tex` 是本项目版本的超集 + 12 个新宏。唯一"本项目独有"的宏
`\qfigmark` 是已废弃机制——新 exporter 改用正文里的原位哨兵（`_SLOT_SENT`）
定位图片，`\qfigmark` 没有调用方了，所以覆盖不丢功能。

**`exporter.py` 与 `exam_template.tex` 必须成对替换**：exporter 生成的
`\qslot*` / `\qsub*` 宏调用只有新模板认得。

### 4. 唯一反复出现的适配：图片寻址

服务器版和本项目的图片寻址完全不同，这是本次改动的**全部实质工作**：

| | 服务器版 | 本项目 |
| --- | --- | --- |
| 正文语法 | `![alt](/qimages/<scope>/<file>)` | `![[文件名]]` |
| 磁盘布局 | `IMAGES_DIR/<scope>/<file>` | `ASSETS_DIR/<文件名>`（扁平） |

三个模块受影响：

- **`exporter.py`**：`_QIMG_EXPORT_RE` 从四个捕获组改为一个（只有文件名——
  双链没有 alt，扁平存放也没有 scope）；正则里 `[^\]|]` 排掉 `|`，因为
  Obsidian 的 `![[图片|300]]` 后缀是**显示宽度**而不是 alt。`_stage_one()`
  改按 `config.IMAGES_DIR / fname` 取图，缓存键从 web 路径改成文件名。
- **`qrender.py`**（页面预览渲染，本项目此前没有这个模块）：新增
  `_asset_src()` 把文件名拼成 `/assets/<file>`，对应 `app.py` 的
  `asset_serve` 路由。不用 `url_for`——本模块的函数也在模板过滤器之外被调用，
  硬依赖请求上下文会让离线调用被迫起 Flask app。
- **`converter.py`**：`_intercept_images()` 改为把图**扁平**写进
  `ASSETS_DIR`，scope 进**文件名前缀**而不是目录（`<scope>_<原名>`）。理由：
  Obsidian 双链按 vault 内**全局文件名**解析，一旦放进子目录，`![[...]]`
  在 Obsidian 里就直接失效。同时丢掉 alt（写进 `|` 后会被当宽度解析）。

**为什么保留 `qrender.py`**：审查过程中曾判定它"耦合 Flask，本项目无 Flask，
应删除"——这是错的。本项目**就是** Flask 应用（`app.py` 59KB，9 个模板），
`markupsafe` 也已在依赖里。这个模块的作用是让**网页预览的版式与 PDF 输出
逐条同源**（选项分列、图片落位都调 `exporter` 的同一批函数），删掉就等于让
两条链各排一套、必然漂移。

### 5. 去多用户化：`converter.py` 的 token

服务器版 `_load_config_for_user()` **强制**要求调用方传入用户自己的 MinerU
token（多人共用一个 MinerU 账号会排队）。本项目单机单人，不存在"每个用户
自带 token"的概念，token 就在 `vendor/project_alpha/.env` 里。

改为 `mineru_token: str = ""`（可选，留空用配置里那份），四个公开入口
（`convert_file_to_blocks`、`convert_exam_and_solution_to_blocks`、
`convert_file`、`convert_exam_and_solution`）同步改成默认空字符串——**参数
本身保留**，这样上游调用签名不用改。

### 6. 修掉一个真实回归：SSRF 防护挡死本地推理

服务器版 `llm_client.py` 带了 SSRF 防护（`validate_base_url()` +
`_PublicOnlyNetworkBackend`）：要求 HTTPS、拒绝内网地址。这在服务器上是
必要的——防止**它的用户**拿服务器去探内网。

但移植过来后，`http://127.0.0.1:11434/v1`（Ollama）被报"Base URL 必须使用
HTTPS"。这是货真价实的回归：单机版用户想接本地推理（Ollama / LM Studio /
vLLM）是完全正当的需求，而这些服务只有 http、只在 `127.0.0.1` 上。

而且单机版的威胁模型不一样：单机版的"用户"就是本机主人，自己连自己的服务
不构成越权，也不存在 API Key 出机器的问题（流量根本没离开 loopback）。

新增 `_is_loopback_url()`，把 loopback 判定**排在 HTTPS 检查和
`resolve_public_ips()` 之前**；`_PublicOnlyNetworkBackend.connect_tcp()` 同样
放行 loopback——**保存时的策略和连接时的策略必须一致**，否则会出现"设置页
存得进去、真去请求时被拦"的诡异现象。

非 loopback 的内网地址仍然照旧拦住。实测：

| Base URL | 结果 |
| --- | --- |
| `https://api.deepseek.com` | 放行 |
| `http://127.0.0.1:11434/v1` | 放行（本地推理） |
| `http://localhost:1234/v1` | 放行（本地推理） |
| `http://192.168.1.5:8000/v1` | 拦住（局域网） |
| `http://api.deepseek.com` | 拦住（非 HTTPS） |
| `https://user:pw@x.com` | 拦住（URL 里带凭据） |

### 7. `config.py` 新增的键

移植来的模块要用几个本项目没有的配置键：

```python
CORPUS_DIR = BASE_DIR / "data" / "corpus"
IMAGES_DIR = ASSETS_DIR
BATCH_CONVERT_CONCURRENCY = 3
EXPORT_CONCURRENCY = 1
```

- `CORPUS_DIR`（OCR 中间产物留档：`_raw.md` / `_blocks.json` /
  `_normalized.md`）**刻意放在 `BASE_DIR` 而不是 `BANK_DIR`**。曾考虑
  `BANK_DIR/".corpus"`，但题库根就是 Obsidian vault，几百份中间产物落进去会
  被 **Obsidian 自己的**搜索和图谱吃掉——`filestore._skip_rel` 只挡得住本应用
  的扫描，管不了 Obsidian。已有的 `.gitignore` 里的 `data/` 一行同时覆盖了它，
  不需要改 `.gitignore`。
- `IMAGES_DIR` 是 `ASSETS_DIR` 的别名，纯粹为了让移植来的模块不用改名字。
- `EXPORT_CONCURRENCY = 1`：单机单人，多个 xelatex 并行只会互相抢 CPU。

### 9. 补上 `qrender.py` 的接线（否则它是死代码）

上面第 4 节把 `qrender.py` 拷进来并适配了图片寻址，但**拷进来不等于用上了**：
模板里三处仍在调旧的 `qimage` 过滤器，`app.py` 也没 import `qrender`——也就是
说结构化渲染一行都没生效，页面版式还是老的"选项挤成一行"。补齐了四处接线：

- **`app.py`**：`import qrender`，新增 `qbody` / `qsolution` 两个模板过滤器。
  **参数传整条记录而不是 body 字符串**：结构判定要用题型和 `img_*` 那几列，
  模板里逐个传参既啰嗦又容易漏，而漏了会**静默**退化成无结构渲染（版式变回旧
  样子却不报错，很难发现）。旧的 `qimage` 保留不动——导入预览的原始文本框那类
  地方不需要结构。
- **字段名对齐**：本项目 `filestore` 的题型字段叫 `type`（frontmatter 里也是
  `type:`），而 `qrender` / `exporter` 沿用服务器版的参数名 `qtype`。在过滤器
  里对齐，两边模块都不改——改任何一边都会波及一批调用方。
- **`static/style.css`**：补上 `.body-structured` / `.q-stem` / `.q-opts` /
  `.q-fig*` / `.q-opt-pair` / `.q-split*` 共约 90 行。本项目的 CSS 此前完全没有
  这套类名（只有 `.q-solution`），不补就是"HTML 结构对了但全无样式"。用到的
  CSS 变量（`--sp-*`、`--surface-2` 等）本项目都已有，无需新增。窄屏那三档
  媒体查询保留且更要紧：**插件把页面嵌在 Obsidian 的侧边窗格里，比独立浏览器
  更常触发窄屏档**。
- **模板**：`index.html`（正文 + 解析）、`recycle_bin.html`、
  `_import_preview.html` 改用 `{{ q | qbody }}`，容器加 `body-structured` 类
  （关掉 `pre-wrap`，否则标签间的换行会被算成空行）。

**验证**：

- 选择题渲染出 `q-opts` 网格；`$a<b$` 正确转义成 `a&lt;b`（先转义再替换图片的
  顺序没被破坏）；输出里没有裸 `<script>`。
- 双链图片渲染成 `/assets/<file>`，正文里没有残留的 `![[` 和 `QFIGSLOT` 哨兵。
- 含中文/空格的图片名经 `quote()` 正确编码（`第一 题.png` → `%E7%AC%AC…`）。
- 空记录 / `None` / 导入预览那种只有 5 个键的字典都不抛错。
- 七个路由仍全部 200。
- **页面与 PDF 同源性实测**：三道选择题分别比对 `exporter.choice_cols()` 算出的
  列数与页面 `data-cols`，全部一致——包括"选项很长因此从 4 列降到 2 列"那道
  （导出 2 列、页面 2 列）。这正是保留 `qrender.py` 的理由：删掉它，页面就得
  自己猜列数，与 PDF 必然漂移。

### 10. 前端资源同步：MathJax CDN → 自托管 KaTeX

第 9 节只补了 `.q-*` 那批新类名。之后做了一次系统性的前端比对（脚本临时写完即
删），发现两类问题，第二类比 CSS 严重得多。

**先说结论：类名覆盖其实没问题。** 逐个扫 `软件版` 模板里用到的 188 个类名，
本地 CSS 覆盖 142 个，剩下的经核对全是 Jinja 片段和 JS 钩子的误抓——唯一疑似
缺失的 `.folder-rename` 实际由 `.folder-act:hover` 通配覆盖着，不是真缺陷。
所以**没有做"整份 CSS 覆盖过来"**，只按规则级差异逐条判断。

**真正的问题：公式渲染走 CDN。** `软件版` 的 `base.html` 从
`cdn.jsdelivr.net` 拉 MathJax 3，而服务器版 2026-08-04 已换成自托管 KaTeX。
在插件场景下 CDN 是不可接受的：**Obsidian 是离线优先的工具，用户断网时整个
题库的公式会全部渲染不出来**。自托管另有两个实测好处（依据在
`static/js/math.js` 顶部）：单公式 117µs vs 1198µs（约 10 倍），主脚本
277KB vs 2.0MB——列表页满屏上千个公式时这个差别能直接看出来。

搬过来的东西：

- `static/js/katex/`（含 `fonts/`，共 60 个文件）+ `static/js/math.js`。
  **这三者的目录结构不能拆开搬**：`katex.min.css` 里字体是相对路径 `fonts/*`。
- `base.html`：删掉 MathJax CDN 那两段，改成三个 defer 脚本（katex →
  auto-render → math.js，**顺序即依赖**，deferred 脚本按文档顺序执行）。
- **首屏防闪**：内联脚本给 `<html>` 加 `.math-pending`，`math.js` 排完摘掉，
  外加 **3s 兜底定时器**——脚本 404 或解析出错时没人来摘这个类，没有兜底就是
  整个题库永久空白。宁可露出 `$...$` 源码，也不能什么都看不见。
- CSS 补 `.math-pending`（用 `visibility` 而非 `display:none`，后者会让容器不
  占高度、公式出现时整页跳动）和 `.katex-display`（收紧行间公式边距 + 长公式
  横向滚动，否则窄窗格里右边被直接截掉）。

**新增 `static_v()` 模板全局函数**（`app.py`）：按文件 mtime 追加 `?v=`。没有
它的话改完 JS/CSS 浏览器会拿旧缓存，表现为"代码明明改了、页面没反应"；
**插件用的是内嵌 webview，自带缓存且没有 Ctrl+Shift+R 可按**，比独立浏览器
更需要。取不到 mtime 时退化成不带参数的普通 URL，不抛错。

规则级差异当时搬了 3 处、**刻意不搬 22 处**（其中 `.bulkbar` 那 11 处已于
2026-08-08 补搬，见下）：

- **搬了**：裸 `<select>`/`<input>` 的主题化背景/边框（宿主是深色主题时这些
  控件会白得刺眼）、`.folder-row` 的 `user-select: none`（不加的话拖文件夹会
  选中文字、留一片蓝色选区）、`.folder-del:hover` 的背景。
- ~~**不搬 `.bulkbar` 那 11 处**~~（**2026-08-08 已补搬**）：当时的判断是"服务器版把
  批量操作栏从底部悬浮胶囊改成了侧栏常驻面板（`grid-column: 1` /
  `position: static` / `display:none↔flex`），而 `软件版` 仍是悬浮胶囊
  （`bottom: 24px` + `transform` 滑入），照搬会直接错位——这是配套另一套布局的
  改动，不是独立的样式改进"。判断本身没错，**结论过期了**：用户 2026-08-08 明确
  要求这一块也同步，于是把配套的布局一起搬了（`#bulkbar` 挪进 `.layout` 当第三列
  + `.bulk-active` / `.bulk-active-page` 两个类由 `syncBulkbar()` 开关）。
  搬"连带样式"必须连它依赖的布局一起搬，单搬样式才是错位的来源。
- **不搬拖拽落点高亮**（`.folder-row.drag-over`、`.is-dragging` 等）：`软件版`
  只有题目排序的拖动，没有"拖题目到文件夹"这套交互，搬了是死规则。
- **不搬 `nav .brand` 的 flex 化**：那是为 logo 图片（`favicon.svg`）准备的，
  `软件版` 用的是 emoji 文字。
- 其余（`.coll-title`、`.folder-pane-head`、`.data-table` 字号等）都是服务器版
  侧栏改版的连带调整，与 `软件版` 现有布局不冲突但也谈不上改进，一并不动。

服务器版另有 375 个 `软件版` 完全没有的选择器，按前缀归类后确认全部属于
**单机版不存在的功能**：`release-*`/`post-*`/`emoji-*`/`auth-*`/`chat-*`/
`profile-*`/`comment-*`/`progress-*` 等（版本说明页、社区、自定义表情、
登录注册、私信、个人主页……）。这些不该搬——单机单人版没有这些页面。

**验证**：无 MathJax/CDN 残留；五个静态资源 URL 都带上了 `?v=<mtime>`；
KaTeX 主脚本、auto-render、CSS **以及字体**（`KaTeX_Main-Regular.woff2`、
`KaTeX_Math-Italic.woff2`）全部 200；三个脚本在 HTML 里的位置严格递增；
`static_v` 对不存在的文件正确退化；七个路由仍全部 200。

## 2026-08-08：补齐导入链路的四个缺口（拖放上传 / 并发 / 总面板 / 拆题审核）

上一节 §10 得出过「类名覆盖其实没问题」的结论，**那个结论是错的**，这里更正。
当时的做法是拿 `软件版` 自己模板里**用到的**类名去服务器版 CSS 里查，全都能查到
就判定同步完成。这个方法按构造就看不见「功能本身在 `软件版` 不存在」的那部分——
模板里没有拖放灰框，自然不会有类名去查它。用户提的「导入界面没有多批任务的看板，
也没有拖动文件的灰色框框」正是这一类。

改用**结构性对比**（两边逐个类名前缀取差集）重查，确认缺 9 个完整类族：
`.dropzone`/`.dz-*`、`.task-*`、`.upload-grid`、`.mobile-only`/`.desktop-only`、
`.bo-*`、`.br-*`、`.btn-danger-text`。它们对应四项功能，全在导入/转换链路上：

### 1. 拖放上传（`static/js/import-upload.js`，新增 ~590 行）

原先方式一~四的交互全写在 `import.html` 的 `{% block scripts %}` 里（~380 行内联
JS），文件选择用的是裸 `<input type="file">`。现在整块搬进 `static/js/`，按服务器版
的前端约定引入（`static_v` + `defer`、IIFE 包住、不留全局变量、JS 里不写 Jinja）。

核心是 `makeDropzone(zone, opts)`：选中的文件存在**闭包里的数组**，不回写
`input.files`——那个属性只读，拖进来的文件本来也进不去。附带的后果是「重置任务卡」
必须整卡重建而不能只清 DOM（`resetTasks()` 里记着这件事）。四处用上了它：方式一的
题干/解析两个框、方式二的 md 多选框、方式四每张任务卡的题干/解析框；方式三的粘贴
框额外支持把 `.md` 拖进去用 `FileReader` 读成文本。

顺带做的两件事：
- **从文件夹导入并自动配对**：按 `(参考答案|答案解析|详细解析|解析|答案|详解|解答)`
  后缀把 `XX.pdf` 与 `XX答案.pdf` 凑成一组；只有解析没有题干的桶让解析自己当题干
  （用户可能就想只导那一份）。
- **修掉 `import.html` 里的死代码**：题卡编辑后的预览重渲染调的是
  `MathJax.typesetPromise`，而 §10 早已把前端换成自托管 KaTeX。表现是编辑题卡后
  预览框里公式退回裸 `$...$` 源码。改为 `window.QMath.typeset(box)`。

上限对齐本地实际：`MAX_GROUPS = 20`（服务器版是 500，配套的是它那套配额与
`task_store`，`软件版` 两者都没有）。CSRF 令牌整套去掉——`软件版` 无鉴权。

### 2. 方式四改为并发转换

`_convert_batch_worker` 原先严格串行（`for i, g in enumerate(groups)`）。改成
`ThreadPoolExecutor(max_workers=config.BATCH_CONVERT_CONCURRENCY)`，默认 3。
`config.py` 里这个常量**早就在了**，只是没人读——串行是当时没接上，不是有意为之。
瓶颈是 MinerU 与 LLM 的网络等待而非本机 CPU，所以并发直接压墙钟时间；上限保留，
免得一次几十组同时打上游接口。

并发的前置条件是 `converter.py` 的中间产物路径已全部绝对化（ADR-024：`os.chdir`
是进程级的，多组并行会串台）。移植过来的这份 `converter.py` 本就是绝对化之后的版本，
所以这一步没有额外改动——但**别再往里加「切 CWD → 干活 → 切回」**。

拆出 `_convert_one_group(batch_id, g)` 承载单组逻辑，`_run_one` 负责起跑前查
`cancelled` 标记并维护 `batch["running"]` 计数。批次字典新增三个键：
`created_at`（总面板按创建时间排「第 N 批」）、`running`（判断整批是否还在动）、
`cancelled`。

### 3. 转换任务总面板（`/batches`）

`batch_id` 只活在内存里，没有落盘的任务列表，所以离开单批看板后就再也找不回来了。
新增 `templates/batches_overview.html` + `static/js/batches-overview.js` +
三个路由（`/batches`、`/batches/status`、`/batch/<bid>/delete`）与
`_batch_overview`/`_all_batches`/`_batch_busy`/`_empty_result` 四个辅助函数。
导航栏加「转换任务」入口，未处理批次数用 `context_processor` 注入
（`nav_batch_count`）——它要出现在 `base.html`，各视图逐个传参必然漏。

两处刻意保留服务器版的行为：删除一批时**已经不存在也返回 `ok=True`**（用户点的是
「让它消失」，两次点击结果该一致），以及 `_batch_busy` 期间**拒绝删除**（正在跑的
组还会往 group 字典里写字段）。丢掉的是 `_own_batch` 归属校验——单用户无此概念。

### 4. 拆题人工审核（把 `converter.finish_block_review` 接上）

`converter.py` 里 `convert_file_to_blocks` / `convert_exam_and_solution_to_blocks`
/ `finish_block_review` 三个函数在移植时一起搬了过来，但**没有任何路由调用**，是死
代码。现在接上：新增 `templates/block_review.html` + `static/js/block-review.js` +
三个路由（`/blocks`、`/blocks/confirm`、`/blockimg/<path:name>`），组状态新增
`awaiting_block_review`（看板 `LABEL` 映射与「审核拆题 →」动作、总面板的
`✂ 待拆题审核` 标签、`_convert_batch_worker` 的终态判定都跟着改）。

前端表单多两项：`block_mode`（`all_ai` 默认 / `manual` 先人工审 / `no_ai` 完全不送
AI）与 `num_template`（题号模板，仅逐题识别有效）。模板写法在提交那一刻就用
`blocksplit.compile_dialect` 编一遍验证、编译结果丢掉——错误挡在前面，而不是等后台
线程跑起来才失败。**占位符是 `x`/`X` 而不是 `N`**（`第X题`、`x.`），提示文案按这个
写；起初照服务器版的 placeholder 写成 `第N题`，验证时才发现那会直接抛

`/blockimg/<path:name>` 的 `name` 完全来自 URL、由用户控制，所以
`safe_join` **和** `base.resolve() in p.resolve().parents` 两道校验都留着——
safe_join 不跟符号链接，少任何一道都不够。

## 2026-08-08（二）：设置页对齐 + AI 重绘配图移植

用户的问题是「就不能和线上的 UI 完全同步吗？设置界面还是不一样，MinerU Token
管理啥的」。§10 与上一节已经两次栽在同一个方法论上：**拿本地模板里用到的东西去
线上查**，查得到就算同步完成。这个方法按构造看不见"功能在本地根本不存在"的那
部分——本地设置页没有 MinerU 面板，自然不会有类名或字段去查它。这一节起改成
**按页面逐个功能点取差集**，不再从类名入手。

### 1. 设置页：MinerU Token 与外观主题

新增两个存储模块与一份改写的模板：

- **`mineru_store.py`**：`has_token()` / `set_token(plain)` / `clear_token()` /
  `resolve()`。Token 与 LLM 的 API Key 同样走 Fernet 加密（复用
  `data/.enc_key`），落 `data/mineru.json`。
  `resolve()` **解密失败时返回空串而不抛异常**：它的调用方是后台转换线程，
  抛出去只会让那个任务莫名失败，日志里还看不出是密钥被换过。
  写入侧是**只写字段**：表单用 `type="password"`，已配置时页面只显示
  `（已设置）`标记，明文**从不回显**。
- **`ui_prefs.py`**：`theme_mode` / `theme_color` / `wallpaper` 三项，落
  `data/ui_prefs.json`。
- **`static/js/settings-theme.js`**：只做即时预览（改颜色/深浅立刻生效，不等
  提交），落库仍走表单 POST。
- **`templates/settings.html`** 改成 `.panel-grid` 四面板：MinerU Token、
  密钥存储、识别模型（LLM）、外观主题。

两处安全决定：

- `theme_color` 必须过 `re.fullmatch(r"#[0-9a-fA-F]{6}")`。它被插值进
  `<html style="--primary: …">`，不校验就是一个 CSS 注入点（实测
  `red;} body{display:none` 会被正确拒掉）。
- `_save_wallpaper` **自己生成盘上的文件名**（`wallpaper_<时间戳><扩展名>`），
  不用上传时带来的名字；`wallpaper_serve` 走 `send_from_directory`（内建
  `safe_join`）。

深浅色与主题色写在 `<html>` 而不是 `<body>`：CSS 选择器是
`html[data-theme="dark"]`，变量得在 `:root` 层被覆盖。这件事在插件场景里**不是
和宿主重复的功能**——iframe 是独立文档，不继承 Obsidian 的主题，宿主切深色时
里面这一页不会跟着变。

### 2. AI 重绘配图（`tikz_render.py` + `tikz_redraw.py`）

MinerU 从 PDF 里抠出来的配图是位图截图，放进导出的试卷里一眼能看出是"拼的"。
移植线上的重绘功能：多模态模型看图 → 输出 TikZ → 编译成矢量图。

**为什么是 TikZ 而不是让模型直接给 SVG**：页面能显示 SVG，但
`exam_template.tex` 用 graphicx，它不认 `.svg`，**导出会静默掉图**；而
SVG→PDF 需要 inkscape / rsvg-convert / cairosvg，本机一个都没有。反方向是现成
的：TikZ →（xelatex）→ PDF →（dvisvgm）→ SVG，MiKTeX 自带这两个（本机已确认
都在 PATH 上）。所以一次编译产出**两份**：页面 `<img>` 用 svg，导出用同名 pdf。
`exporter._stage_one` 里"见到 `.svg` 就换成同名 `.pdf`"那段代码**早就在了**，
所以排版链一行没改。

文件名是 `tikz_<sha256(code)[:16]>`，内容寻址：同一段代码重复渲染直接命中缓存，
不同题生成了相同的图自然共享一份。也因此**生成物一律不删**。

与服务器版唯一的实质差异是落盘位置：那边 `IMAGES_DIR/<scope>/` 按用户分目录，
单机版图片扁平存在 `_assets/` 下，故 `render(code)` 去掉了 `scope` 参数。

**三道沙箱闸原样搬来，一道都不能少**（TikZ 是图灵完备的 TeX，编译模型输出等于
执行不可信代码）：

1. `_FORBIDDEN` 黑名单（`\write18` / `\input` / `\usepackage` / `\directlua` /
   `\csname` / `\catcode` …）；
2. 编译带 `-no-shell-escape`；
3. `openin_any=p` / `openout_any=p` 环境变量，禁止读写工作目录之外。

这三道与"外网能不能访问"无关。本应用只监听 `127.0.0.1`、没有登录，但不可信内容
来自**模型**，而题库目录里是用户全部的题和图——一个 `\input` 就能把它们读出来
回显。

`tikz_redraw.py` 侧的三条不变量：

- **原图一律保留。** 应用重绘只改正文里的引用（`![[a.jpg]]` →
  `![[tikz_x.svg]]`），jpg 文件不删，原文件名记进 frontmatter 的
  `img_originals`，随时能退回。
- **不信客户端给的路径。** `/redraw/apply` 收到的名字必须过
  `validate_generated()`：只接受 `tikz_<16位hex>.svg` 且同名 pdf 在位。缺 pdf
  也要拒——那种"页面能看、导出掉图"的半成品最难查。`/redraw/restore`
  **只收 index**，原文件名一律从 frontmatter 读。
- **按序号替换，不用 `str.replace`。** 同一张图在正文里出现两次时 replace 会把
  两处都改掉（与 `qrender.swap_image_refs` 同一取舍）。

图片引用正则换成 Obsidian 双链 `!\[\[([^\]\|]+)(?:\|[^\]]*)?\]\]`（一个捕获组、
没有 alt），并**实测与 `qrender._QIMG_RE` 同序**——两边对"第几张图"的计数必须
完全一致，不然设置的是这张、重绘的是那张。

LLM 配置走 `providers.resolve("redraw")`，与服务器版的 md/重绘用途拆分对齐
（`db.PURPOSES` + `llm_provider.resolve(conn, uid, purpose)`）。

> **更正（2026-08-08）**：这一节原先写的是「LLM 配置走 `providers.resolve_active()`；
> 服务器版那边 md/重绘分用途的 `resolve_for_user_id(uid, purpose=...)` 没有移植
> （单机版只有一套配置）」。那个省略的实际后果是**重绘功能整个死掉**、从上线起
> 一次都没成功跑过：唯一的 `active` 必然是用户配来做导入识别的文本模型
> （`deepseek-chat` 之类），`chat_vision` 那一步必然报错，而错误提示还只说
> 「还没有启用的识别模型配置」——已经配过模型的用户完全无从下手。
> 现已补上用途拆分：`data/providers.json` 里 `md` 沿用老键 `active`、新增
> `active_redraw`（老文件不需要迁移），`resolve("redraw")` 解析不到时回落到 `md`
> 那套、反方向不回落，设置页给两列独立开关。
> 教训记在 `docs/MEMORY.md`：**这类「单机版用不上，不移植」的省略要按「功能还活着吗」
> 验收，不是按「代码搬全了吗」**——本节其余四样（提示词、路径、入口、产物处理）
> 当初都搬对了，只少了配置面，看文档反而觉得一切正常。

`max_tokens` 就地抬到 `MIN_REDRAW_TOKENS = 16000`（只作用于这一次调用，不改用户
存的配置）：provider 常配 8192，TikZ 代码加上思维链很容易超，一超就截断成半截
代码、编译必失败。

### 3. `filestore` 的 `img_originals`

本地 frontmatter 里此前没有这个字段。新增 `_KNOWN_DEFAULTS` 项 + `_to_record`
字段 + 三个函数，列表结构照 `set_img_layout` 的 `[{"i": 0, ...}]` 模式：

- `remember_img_original(qid, index, filename)`：**首次写入即锁定**。重绘可以连点
  多次（对第一版不满意再生成），第二次时正文里已经是 `tikz_*.svg` 了；每次都覆盖
  的话原图就永久丢了引用，"还原"会把用户退回上一版 TikZ 而不是最初的照片。
- `get_img_original(qid, index)`。
- `forget_img_original(qid, index)`：还原后**必须**删记录，否则"还原原图"按钮一直
  亮着、点了却没有任何变化，像坏了一样。

### 4. 前端：四个路由 + `image-redraw.js`

`app.py` 加 `_redraw_jobs` / `_redraw_jobs_lock` / `_REDRAW_JOB_TTL = 1800` 与四
个路由（发起 / 轮询 / 应用 / 还原），做法与转换任务共用同一套"内存字典 + 锁"
（本地单用户，关服务即丢，无需 Celery）。两处刻意保留服务器版的行为：

- `_redraw_worker` 的最外层**兜住裸 `Exception`**。漏出去的话任务永远停在
  `pending`，前端一直转圈到超时，用户拿不到任何错误信息。
- 任务失败时 `/redraw/status` **仍回 200**——"查询"这个动作是成功的。回 4xx/5xx
  会让前端的 fetch 分支把它当网络故障处理，看不到真正的原因。

`static/js/image-redraw.js`（~300 行）三个不太显然的决定：

- **应用/还原之后绝不 `location.reload()`。** 一页上可能有好几道题同时在重绘，
  刷新会把其它卡片正在跑的轮询循环连同 job_id 一起销毁——任务在后端照样跑完，
  前端再也拿不到结果。所以只整块替换这张卡的题干 HTML。
- job_id 存 **sessionStorage** 而不是 localStorage：重绘要几十秒，用户很可能切走
  再回来，凭 job_id 能重新接上；但这种"接上"只在同一标签页里有意义，
  localStorage 会让另一个标签页也去认领同一个任务。
- `readJSON()` 而不是直接 `res.json()`：网关超时返回的是 HTML 502/504 页面，
  `res.json()` 撞上它抛 `Unexpected token '<'`，用户完全看不懂。

预览弹窗用原生 `<dialog>`（自带焦点陷阱和 Esc）。图片 `src` 与 TikZ 源码一律用
DOM 属性赋值（`img.src` / `pre.textContent`），**不拼 innerHTML**——那段代码来自
模型，拼进 HTML 就是一个 XSS 面。

**`window.QImgLayout` 是这次补出来的。** 服务器版的 `replaceBody` 在
`static/js/image-layout.js` 里，而单机版的图片排版脚本还内联在 `index.html` 的
`{% block scripts %}` 里，压根没有这个模块。做法是把原来写在 `forEach` 回调里的
初始化逻辑抽成命名函数 `initImgLayoutBar(bar)`，再暴露同名接口——换完题干 HTML
后必须重跑它，否则新 `<img>` 节点上没有 `.qimg-resizable` 和缩放手柄，重绘之后
这张卡的缩放/对齐就失灵了。同时补 `QMath.typeset(body)`：新 HTML 里的公式还没
排版过。

`.img-layout-bar` 加 `data-originals` 与两个按钮（`.img-redraw-btn` /
`.img-restore-btn`），CSS 补 `.redraw-*` 一族。弹窗里图片垫**白底**——重绘出来的
SVG 是黑线透明底，深色模式下不垫等于什么都看不见。

顺带修了 `base.html` 的插件桥：点击上报原先只排除
`a, button, input, select, textarea, label, summary`，而控制条上的对齐/大小/分栏/
重绘全是 `<span>`，点一下会连带在相邻窗格打开这道题的 md——调个版式却弹出一个
笔记。现在把 `.img-layout-bar` / `.qimg-resizable` / `.redraw-dialog` 一并排除。

## 2026-08-08（三）：核心链路的六个缺口（导出模板 / 批量落点 / 免审入库 / 多 Token）

用户的话是「导出时的模板已经进行了修改，你有同步吗？…这些根本不是无关紧要的
装饰性内容，而是最关键的内容啊，现在我要求核心功能链路：上传，管理，导出，一个
不许落」。前面三节的方法论问题（拿本地有的去线上查）已经更正过，这一节按
**上传 / 管理 / 导出三条链路逐个功能点**取差集，查出六个缺口，全部补齐。

### 1~3. 导出链路：分值与解析配图布局没接上

三处都是「后端算好了、前端也填了，但中间那一段没接线」，症状是**改了设置导出的
PDF 却毫无变化**——比"报错"难查得多。

- **`sol_img_layouts` 没传给 exporter**：正文配图的 `img_layouts` 一直在传，解析
  里的配图布局（缩放/对齐/分栏）却在调用处漏了。补上时把两处都改成关键字传参
  （`field=`），下次再加一种布局不会又插错位置。
- **`section_points` 键名不对**：导出页发上来的是四个分项，而 exporter 读的是另一
  套键名，于是每题分值永远吃默认值。按 exporter 侧的键名对齐（模板是排版的下游，
  改它波及 tex）。
- **`index.html` 缺四个分值输入框**：线上组卷面板有「选择/填空/判断/解答各多少分」
  四个数字框，本地只有一个总分。补齐四个 `type="number"` 输入，名字与上一条对齐。

### 4. 该批全部放入同一文件夹

线上是批量上传时勾一个开关、填个文件夹名，整批题都落进那个文件夹。本地
`import.html` 缺这个开关，`_import_preview.html` **连「打包为文件夹」这个控件都
没有**（只有一个「导入目标」下拉），所以这一项比原计划大一圈：前端两处、后端两处。

- `import.html` 新增 `batch-pack-cb` + `batch-folder-name`，`import-upload.js` 里
  `syncPack()` 管显隐、提交时按 `pack_folder` / `pack_folder_name` 发上去。
- `batch_convert_create` 读进批次字典（整批共用，各组转完各自读）。
- `batch_group_review` 把 `pack_folder_name` 带到校对页，**预填并自动勾上**新补的
  「打包为文件夹」控件——不然每组还得手打一遍同一个文件夹名。
- `import_md` 的确认分支：试卷模式优先于下拉选的文件夹（`final_col` /
  `folder_note`），撞同名时**复用而不是报错中断**。题这时已经入库了，为一个目录名
  把整批校对成果丢掉不值得。

配套在 `filestore.py` 新增两个函数（线上的 `_get_or_create_folder` 在本地的
「一题一 md + 目录即文件夹」模型下没有对应物）：

- **`safe_folder_name(name)`**：文件夹名会来自**上传文件名**（下一节的按文件名
  建组），而 `folder_id` 是直接拼进 `BANK_DIR` 的相对路径，带一个 `../` 就能把题
  写到题库外面去。**处理顺序有讲究**：先换路径分隔符和 Windows 保留字符，**再**
  循环消 `..`。反过来写的话 `../..` 会剩下 `..`（`strip(".")` 只削首尾）——第一版
  就是这么写的，被测试抓到。
- **`get_or_create_collection(name, parent)`**：`create_collection` 撞同名会抛
  `ValueError`，而自动入库那条路上没人在场回答「换名还是并进去」，所以复用同名。

### 5. 不审核直接入库

转换成功后不停下来等人校对，直接按默认值落库。前端三个层叠开关，后端**照抄线上的
层层依赖**：`per_task_folder` 要求 `auto_import`，没勾上一级的下一级直接按 `False`
收——不这么写，前端隐藏起来的子选项被人手动 POST 上来就会生效。

- `_auto_import_after_convert(batch_id, grp, batch)`：默认值与「校对页什么都不改」
  **完全一致**（题型走 `importer.guess_type`，难度/标星留空、不加标签，查重标为
  「重复」的一律不导——校对页默认也是不勾）。任何异常都把这一组标成 `error` 并提示
  「点重新转换」，不能让它卡在不死不活的状态。
- **在批次锁之外调用**。入库要扫题库查重、写一堆 md，占着 `_batch_jobs_lock` 会
  拖住同批其它并发组的状态更新（方式四并发 3 组）。
- **免审否决 manual**：`if auto_import and block_mode == _BLOCK_MODE_MANUAL:
  block_mode = _BLOCK_MODE_ALL_AI`（同线上 `import_convert.py`）。勾了「整批免审」
  就是要求全自动，不能停下来等人。`no_ai` 只是不送 LLM，与免审不冲突。
- `_auto_import_folder`：两个开关独立生效——`pack_folder_name` 全批一个文件夹，
  `per_task_folder` 每组一个以文件名命名的文件夹（同时勾则挂在批文件夹下），
  文件名取不出来时退化成 `任务N`。落库直接用 `create_question(folder=...)` **建在
  目标文件夹里**，不走「先落根目录再 `add_to_collection`」——后者是移动文件，多一
  次 IO。

**这一项少搬了一个子选项：线上的「一并保存原卷」（`auto_keep_original`）没有移植。**
它依赖服务器版的原卷存储（`collection_papers` / `papers.store`），而 `软件版` 完全
没有「原卷」这个概念——没有表、没有目录、没有页面入口。要不要在本地造一份，需要
先定「原卷存哪、怎么和题关联、页面上从哪进去」，不是照搬能解决的。

> **上面这段已作废，见文末《一并保存原卷》。** 这个判断是错的：vault 里的文件夹
> 就是真目录，原卷直接 copy 进去即可，那三个问题自己就答了。

### 6. 多份 MinerU Token 轮转（新增 `mineru_pool.py`）

线上有这个模块，本地没有。多份 token 的用处**不是「切换」而是并行**：方式四同时
跑 3 组，单个 MinerU 账号的并发与额度都有限，几组挤同一个 token 会互相排队甚至
报超额。

- **`mineru_store.py` 改成多份存储**：文件格式
  `{"tokens": [{"id", "label", "token_enc", "added"}]}`，老格式
  `{"token_enc": ...}` 加载时**就地升格成列表、不改写文件**。新增
  `list_tokens()`（**只给 id/备注/时间，密文与明文都不出现**）、`add_token`、
  `remove_token`、`resolve_all()`（解不开的跳过记日志、保序去重）。
  `set_token()` 保留「替换全部」的旧语义并在 docstring 里写明**不要改成追加**。
- **`mineru_pool.py`**：进程内 `_inflight` 计数，`acquire()` 挑当前最空闲的一份，
  `release()` **必须写在 finally 里**——漏一次计数就只增不减，之后的调度会永远
  避开一个其实已经空闲的 token。
- **`_convert_with_pool_retry(make_call, token)`**：`ConvertError` 时换一份最空闲
  的重试一次；只存了一份时不重试（同一个再跑一遍只是白等）。**它只 release 自己借
  的那个重试 token，传进来的 token 由调用方在自己的 finally 里还**——第一版让它
  代还，结果 `_convert_one_group` 的 manual 分支是 `return` 出去的、又可能调它两
  次，双重归还与漏还同时存在。谁 acquire 谁 release，分支再多也不会漏。
- **设置页语义变了：从「替换」改成「追加」**。原先「留空提交＝清除」，能存多份之后
  那会变成「留空提交把我攒的几份全清了」，代价大且不可撤销。清除改成每条自己的
  删除按钮（`/settings/mineru/delete`，按 id）。
- 与线上的**刻意分歧**：那边的池子是「管理员加的 ∪ 白名单用户自己填的」，要查库、
  判 `mineru_whitelisted`、还要区分「自己的 token」和「借来的」（只有借来的才重试，
  免得偷偷花别人额度）。本地单用户没有别人，这套区分整个消失，池子就是
  `mineru_store` 里的全部。理由写在 `mineru_pool.py` 的模块 docstring 里。

  转换时报解密错，比显示「没设置」这种误导好；

  release 归零后下一次挑回它；release 空串 / 未知 token / 重复 release 都不会把计数
  压成负数；
- `acquire_retry` 确实排除掉刚失败的那份；只存一份时返回 `None`；
- `_convert_with_pool_retry`：失败→换另一份→成功，且重试的 token 已归还；两份都
  失败时抛**原始**异常且计数归零；**非 `ConvertError` 不重试**（不该拿另一份额度
  重跑一个代码 bug）；
- 50 线程并发 acquire/release 后计数**全部归零**。

测试用 `QUIZFORGE_BANK` 与 `config.MINERU_TOKEN_PATH` 双双指到临时目录，真实题库
与 `data/mineru.json` 未被触碰；两份临时脚本用完即删。

**未验证**：真实 MinerU 多账号的并发效果（要两个真账号 + 额度）。另外**模板与 CSS
的改动要重启后端才生效**（同上一节）。

## 2026-08-08（四）：一并保存原卷（补上第 5 节漏掉的那个子选项）

上一节写「`auto_keep_original` 不是照搬能解决的，得先定原卷存哪、怎么和题关联、
页面上从哪进去」。**这个判断是错的**，原话：「保存原卷在 Obsidian 中不是最好实现了
吗？直接放在建立的文件夹中就行了啊」。

确实如此，而且三个问题在 vault 模型下**自己就答了**：

| 问题 | 服务器版 | 本地（vault） |
| --- | --- | --- |
| 存哪 | `papers.store` 独立目录 + `collection_papers` 表 | 就是题所在的那个文件夹 |
| 怎么和题关联 | 表里一行外键 | **同目录共处**，不需要任何记录 |
| 从哪进去 | 专门做一个附件列表 UI | Obsidian 的文件浏览器 + 自带 PDF 阅读器 |

服务器版之所以要那张表、那个独立目录、还要一套孤儿文件清理，**只是因为它的
「文件夹」不过是一行数据库记录，附件无处可放**。本地的文件夹是真目录，这三样东西
在这个模型下没有对应物，一并蒸发——这不是偷懒省略，是需求本身消失了。

顺带白拿的几件事，都是因为落点是真目录：

- `delete_collection` 是把整个子树 `shutil.move` 进 `.trash/`，**原卷跟着文件夹一起
  进回收站、一起恢复**，不用额外写一行代码（已验证）。
- 导出/备份/同步整个目录时原卷天然在内。
- 保存失败也无所谓：用户自己拖一份进那个文件夹就行，没有任何门槛。

### 落地要点

- **`filestore.paper_filename(display_name, kind)`**：名字来自上传文件名，会被拼进
  `BANK_DIR`，所以和 `safe_folder_name` 同样必须收（路径分隔符、`..`、Windows 保留
  字符）。但**扩展名必须保留**——Obsidian 靠扩展名决定能不能点开，丢了扩展名的 PDF
  在 vault 里是个打不开的死文件。stem 截到 60 字。空名按 `kind` 退化成
  `原卷`/`答案`：两份都退化成同一个名字的话，题干和答案会在同一目录里撞名，后存那
  份被加随机后缀，谁是答案就再也看不出来了。
- **`filestore.store_paper()` 是 `shutil.copy2`，不是移动**。这一点非改不可：那份
  临时文件在整批审核期间还要供「重新转换」和左侧原文对照（`/convert/file/<job_id>`）
  用，移走了两个功能当场坏掉。整批结束时 `_maybe_finish_batch` 会统一删临时文件，
  副本不受影响（这条已单独写成断言验证）。同名不覆盖，加随机后缀——同一个文件夹里
  可能导入两份同名试卷（比如扫描了两次）。
- **原卷不会被当成题目**：`_scan()` 只 `rglob("*.md")`，PDF 在它眼里不存在；文件夹
  计数也不含它（已验证）。也不能放 `_assets`——那儿是正文引用的图片，且被
  `_skip_rel` 排除。
- **路径绝不从表单收**，一律用 `_source_paper_files()` 从调用者自己的
  `_jobs`/`_batch_jobs` 条目里查出来。收表单路径等于开一个「把本机任意文件复制进
  题库」的接口。查不到（粘贴 md 进来的、任务已被清掉的）就返回空列表、静默跳过。
- 顺手补了个原有缺失：`convert_start` 的 `_jobs` 条目**以前不记 `solution_path`**，
  方式一那条路的答案卷根本查不到。
- **层级照抄服务器版**：`auto_import` → `per_task_folder` → `auto_keep_original`，
  后端重新按层级收一遍（`auto_keep_original = per_task_folder and ...`），手工 POST
  一个隐藏子选项也不会生效。没有落点文件夹时不存——原卷摊在题库根会和题目混在
  一起，而且再也认不出属于哪一批。
- **两个前端入口都在**（「前端的入口也别少」）：方式四的第三级勾选框
  （`batch-keep-original-cb`，缩进 40px，跟着上一级显隐），以及校对页工具栏的
  「一并保存原卷」（默认勾上，跟着「打包为文件夹」显隐）。校对页那个只在有
  `job_id`/`batch_id` 时才渲染——粘贴 md 进来的没有原文件可留，勾了没反应最恼人。

### 验证

两份临时脚本（用完即删），`QUIZFORGE_BANK` 指向临时目录，真实题库未被触碰：

- **57/57 断言通过**：`paper_filename`（扩展名保留、`..`/分隔符/保留字符被收、
  过长截断、空名按 kind 退化、纯点名）、`store_paper`（是复制不是移动、同名加后缀

## 2026-08-08（六）：设置页填了 MinerU token 仍报「请在 .env 中填写」+ 导入页三处对不上

起因是实际点「开始转换」报错。顺着查出一个真 bug 和三处 UI 差异。

### 1. `.env` 校验挡在替换之前（真 bug，会让整条导入链完全不可用）

`converter._load_config_for_user` 先调 project-alpha 的 `load_config()`，**之后**才
`dataclasses.replace` 把用户的 token 换进去。而那个 `load_config()`
（`vendor/project_alpha/src/config.py:29-36`）硬性要求 `MINERU_API_TOKEN` 与
`DEEPSEEK_API_KEY` 两个环境变量都非空，缺一个直接抛
`ConfigError("请在 .env 中填写")`。于是只要 `.env` 是空的，**设置页存了什么都没用**
——token 还没轮到被使用就已经报错了，而且报的错指向一个软件版根本不该要求用户碰的
文件（MinerU token 走 `mineru_store` 加密存储，LLM 走 `providers.json`）。

服务器版没这毛病：它在校验前往环境里补了个占位值
（`quizbank-web/converter.py:249-250`，注释写着「project-alpha 的 .env 里这一项是否
可读不该卡住 QuizForge 的转换」）。移植时这两行没跟过来。

修法照搬那个思路，但要补的是**两个**键（服务器版只补了 MinerU 那个，因为它的 `.env`
里 DeepSeek key 一直是有值的；软件版两个都可能空）。新增模块级常量
`_ENV_PLACEHOLDER`，因为「有没有真配置」现在要靠**比对取到的值是不是这个占位串**
来判断，不能再看是否为空：
- `_load_config_for_user`：补占位 → `load_config()` → 有传入 token 就替换；没传入
  且拿到的就是占位串 → 抛「请在设置页填入」那条明确提示（保住原有的报错语义）。
- `_load_llm_fallback_cfg`：原来只补 `MINERU_API_TOKEN`，照样会因 `DEEPSEEK_API_KEY`
  为空炸掉，补齐两个。
- `_make_llm_client`：**占位串绝不能当真 key 用**。provider 为 None 且 `.env` 里也
  没有 key 时直接抛 `ConvertError`，否则拿 `placeholder-…` 去请求，用户收到的是一个
  看不懂的 401，而真正的原因是「既没在设置页配 LLM、`.env` 里也没有 key」。

复现与验证都用真实存储跑（没打桩）：修前 `resolve_all()` 拿到 1 份 51 字符的 token、
解密正常，而 `_load_config_for_user` 抛 `ConfigError 缺少 MINERU_API_TOKEN`；修后
五项全过——传入 token 时解析成功且值与存储一致、一份都没存时报「请在设置页填入」、
回落配置不再抛 `ConfigError`、假 key 被拦下并给出可读提示、provider 路径正常。

### 2. 「不审核直接入库」与「先人工审核拆题结果」前端不联动

`app.py:1079` 明确会把 `auto_import + block_mode=manual` **静默否决**成 `all_ai`
（免审就是要求全自动，停下来等人自相矛盾）。服务器版
`import-upload.js:218-231` 对此做了联动：勾上免审时把 `<option value="manual">` 设为

### 3. 「一并保存原卷」默认值自相矛盾
