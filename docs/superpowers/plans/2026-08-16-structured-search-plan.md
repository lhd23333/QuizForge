# 结构化搜索与当前范围约束实施计划

> 实施范围：软件版题库首页搜索。保持单一 `q` 参数，不引入全文索引或新依赖。

## 目标与验收

- 普通文本继续兼容原有搜索，并补充题源字段；搜索对象是当前逻辑题目范围，而不是整个题库，也不是当前已加载的卡片。
- 支持 `tag:`、`content:`、`solution:`、`source:`、`type:`、`difficulty:`、`starred:`，多个条件按 AND 组合，带空格的值可用双引号包裹。
- 当前文件夹／全部题目状态及标签、题型、难度、星标筛选均与搜索取交集；搜索、切换筛选和清除搜索时不得意外丢失当前范围。
- 无法解析的引号和非法 `starred` 值显示明确错误，不静默退化成扩大范围的搜索。
- 为后续预设标签树保留父标签展开接口，但本阶段不引入标签树数据结构。

## 任务一：建立纯搜索解析与匹配核心

**文件：**

- 新增 `search_query.py`
- 新增 `tests/test_search_query.py`

1. 先写失败测试，覆盖普通搜索、字段搜索、引号值、多条件 AND、未知前缀按普通文本、非法布尔值、未闭合引号，以及可选标签后代解析器。
2. 运行 `python -m unittest tests.test_search_query -v`，确认测试因模块或行为缺失而失败。
3. 实现无文件 I/O 的解析器与记录匹配器：使用 `casefold()`；普通文本搜索题干、解析、标签和题源；结构化模式仅在至少出现一个受支持字段时启用。
4. 再次运行该测试文件，确认全部通过。

## 任务二：接入题库查询并保证旧调用兼容

**文件：**

- 修改 `filestore.py`
- 修改 `tests/test_filestore_batch.py`

1. 先增加失败测试：字符串搜索仍可直接传入，题源能命中，结构化条件与现有 collection／tag／type／difficulty／starred 范围取交集。
2. 让 `list_questions()` 同时接受原始字符串和已解析查询对象；字符串由内部解析，以兼容现有调用者。
3. 保持筛选和排序顺序不变，仅替换搜索判断。
4. 运行相关单元测试并确认通过。

## 任务三：路由、全选与页面范围保持

**文件：**

- 修改 `app.py`
- 修改 `templates/index.html`
- 修改 `tests/test_core_reliability.py`

1. 先写路由失败测试，覆盖：
   - 搜索结果只来自当前 collection 或当前全部／筛选范围；
   - 搜索表单保留范围参数；
   - 清除按钮只移除 `q`；
   - 文件夹和筛选切换保留 `q`；
   - `/select_all` 与页面搜索使用同一解析结果；
   - 解析错误保留原查询、显示错误且不返回扩大后的结果。
2. 在入口路由只解析一次查询，将对象交给 `filestore`，并把错误转成页面提示；非法查询结果置空。
3. 提取白名单范围参数，供搜索表单隐藏字段及“清除搜索”链接复用，保留重复标签参数且不复制 `q`。
4. 调整文件夹／筛选导航，使它们修改自己的参数时保留当前 `q`；明确“清除搜索”是唯一主动移除 `q` 的操作。
5. `/select_all` 复用相同的解析与错误处理，保证批量选择范围和可见搜索结果一致。
6. 运行核心可靠性测试和前端测试。

## 实施约束

- 不改变 Markdown 题库格式，不引入数据库或搜索索引。
- 不直接修改安装目录中的零散文件；安装版只通过 `DirectBundle` 原位覆盖。
- 搜索范围指当前筛选后、分页／无限滚动前的完整逻辑集合。
- 本阶段所有字段条件按 AND；不实现括号、OR、NOT、通配符和模糊匹配。
