# QuizForge 0.17.0-beta 稳定化与发布设计

## 目标

按顺序完成四个阶段：整理并提交当前工作区；复核完整测试并固化一键验证；对 `app.py` 与 `exporter.py` 做最小职责拆分；生成 `0.17.0-beta` 安装包，隔离验证从 `0.15.3-beta` 原位升级，最后提交并创建 annotated tag `v0.17.0`。

## 全局约束

- 当前用户数据和日常安装目录不得用于降级试验；旧版覆盖测试必须在临时目录与隔离的应用数据目录中执行。
- 不更换许可证公钥、签发私钥或加密根密钥，不新增联网授权与自动更新能力。
- 不删除真实题库、图片或 `%LOCALAPPDATA%\QuizForge` 用户数据。
- 只拆分职责边界清晰、可由现有行为测试覆盖的代码，不进行蓝图化或大规模目录重构。
- 每个阶段完成后运行与该阶段风险相称的验证，并向用户单独报告。

## 阶段一：可信 Git 基线

确认 `$out/` 是字体探测产物、`_pre_sync_backup/` 是同步前代码副本，两个异常文件是 Playwright 命令输出；删除这些确定的临时产物，并在 `.gitignore` 中加入可复现的临时目录规则。检查未跟踪文件中没有凭据和真实用户数据，运行现有发行扫描与语法检查，然后把当前 `0.17.0-beta` 功能按可回滚主题提交，形成干净基线。

## 阶段二：完整验证入口

重新运行 Python、前端、Python 语法、JavaScript 语法、Jinja 模板和发行文件扫描。若仍有失败，先复现根因，再以回归测试驱动修复；环境相关测试只能在证明其不属于产品缺陷后显式隔离，并保留可见说明。最终提供一个仓库内统一验证入口，任何子命令失败都返回非零退出码。

## 阶段三：最小职责拆分

先用导入与路由契约测试锁定现有行为，再选择两个低耦合边界：从 `app.py` 抽离不依赖 Flask 全局请求状态的纯辅助逻辑；从 `exporter.py` 抽离独立的排版或格式化纯函数。原模块继续重新导出既有名称，避免调用方和测试大面积改动。拆分后除导入方向和文件归属外，行为、路由、模板变量及导出产物保持不变。

不在本轮执行：把 `app.py` 全面改成蓝图、重写导出器、修改题库格式、修改 OCR 流程、增加第三方依赖。

## 阶段五：安装包与升级验证

使用现有 `build_installer.ps1` 生成 `QuizForge-0.17.0-beta-Setup.exe`，检查版本资源、发行扫描结果、文件大小与 SHA-256。使用现有 `0.15.3-beta` 安装包在临时目录静默安装，并将应用数据重定向到临时位置；放入仅用于测试的哨兵配置后，再运行新安装包覆盖同一目录。验收项包括：程序版本变为 `0.17.0-beta`、固定 `AppId` 对应的卸载器仍存在、旧程序目录被正确覆盖、隔离用户数据哨兵保持不变、程序可启动且健康接口返回成功。

隔离验证通过后更新 `README.md`、`README.en.md`、`docs/STATUS.md` 与 `docs/CHANGELOG.md` 中“未生成安装包”的状态，提交发布记录，创建 annotated tag `v0.17.0`。不自动推送远端。

## 失败处理

- 任何测试或发行扫描失败都停止进入下一阶段，保留日志并先处理根因。
- 临时升级验证失败不得改用日常安装目录继续尝试。
- 如果旧安装包无法静默安装到隔离目录，则只报告安装包构建完成，不能宣称已验证旧版覆盖。
- 如果 Git 中发现疑似凭据或真实数据，停止提交并先报告具体文件，不通过忽略规则掩盖问题。

## 验收标准

1. 工作区只包含预期源码与文档，阶段提交边界清晰。
2. 统一验证入口一次执行即可复现全部离线检查，退出码为 0。
3. 最小拆分前后完整测试结果一致，公开导入与运行行为不变。
4. `0.17.0-beta` 安装包生成，并在隔离环境完成从 `0.15.3-beta` 的覆盖安装验证。
5. 发行文档、提交和 `v0.17.0` annotated tag 与实际产物一致。
