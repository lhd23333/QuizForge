# QuizForge 好题好卷好资料导入工作站设计

日期：2026-10-04  
状态：待用户审阅  
范围：架构设计，不包含本文件之外的代码实施

## 1. 目标与非目标

QuizForge 的产品定位扩展为本地内容加工工作站：把好题、好卷、好资料目录中的稳定文件送入 OCR/识别链路，转换为可预览、校对、重排、组卷和导出的独立题卡。三类输入都使用统一的题卡存储方式，但各自保留不同的内容组织语义。

本设计不替换现有 MinerU、Doc2X、本地 MinerU、`whole`、`block` 或 `no_ai` 能力；不改变现有手动导入、题库扫描、题卡编辑和 PDF/TeX 导出的兼容格式。自动导入是其上的编排层。

## 2. 用户确认的产品语义

### 2.1 三个 Profile 与六个目录

固定 Profile：

- `good_question`：好题
- `good_paper`：好卷
- `good_material`：好资料

每个 Profile 有独立的 `input_dir`、`output_dir` 和 `enabled` 监听开关。默认目录为当前题库根目录下的 `好题`、`好卷`、`好资料`，且默认输入目录等于对应输出目录，即原地替换。六个目录均可自定义，也允许位于当前 `BANK_DIR` 之外的其他本地磁盘目录。

路径必须是可验证的本地普通目录：程序创建不存在的目录，验证可读写性，拒绝网络 UNC 路径、不可解析路径和符号链接越界；不把外部目录强行纳入题库扫描。目录设置保存在题库隔离的本地状态 JSON，不写入题卡 Markdown。

建议配置形状：

```json
{
  "good_question": {"input_dir": ".../好题", "output_dir": ".../好题", "enabled": false},
  "good_paper": {"input_dir": ".../好卷", "output_dir": ".../好卷", "enabled": false},
  "good_material": {"input_dir": ".../好资料", "output_dir": ".../好资料", "enabled": false}
}
```

### 2.2 原地替换与系统回收站

自动转换永远先在独立临时工作区完成 OCR、切块、题卡生成、资源复制和质量校验。输出清单全部验证成功并提交后，源文件才发送到 Windows 系统回收站；不使用 QuizForge 内部 `.trash` 代替系统回收站，也不直接 `unlink`。

输入输出目录相同时，用户看到的是原文件被输出物替换；目录不同时，输出写入自定义目录，源文件仍在完成提交后进入系统回收站。输出失败、校验失败或回收站调用失败不得永久删除源文件。回收站失败时保留已提交输出，任务进入 `recycle_pending`，只重试回收动作，不重新生成版本。

### 2.3 永久版本与递增序号

每次成功转换都保留独立版本，绝不清理或覆盖旧结果。第一次使用基础名，后续使用 `_2`、`_3`……；序号按目标目录内现存结果分配，并在版本登记锁内提交，避免并发冲突。失败重试不占版本号；只有完整输出提交后才消耗序号。

同一输入路径且内容哈希未变化时不重复转换。内容变化时视为新版本，即使路径相同也生成下一个独立序号。版本登记至少包含 `version_id`、Profile、源路径、源内容 SHA-256、输出路径、序号、任务 ID、状态、时间、输出清单哈希和回收站状态。

## 3. 组件边界

新增模块建议如下：

- `source_settings.py`：六个目录、监听开关、默认目录、路径校验和原子配置保存。
- `source_ingest.py`：统一监听器、稳定性判定、去重、队列、暂停、恢复和重试。
- `source_profiles.py`：三个 Profile 的识别、切块、命名、题卡元数据和输出清单生成。
- `source_versions.py`：内容指纹、版本注册表、序号分配、提交幂等性和版本查询。
- `source_recycle.py`：Windows Shell 系统回收站适配和 `recycle_pending` 重试。

现有模块继续作为下层能力：`converter.py` 提供 OCR 统一入口；`blocksplit.py`、`blockpipe.py`、`collection_structure.py` 负责既有切块和质量检查；`filestore.py` 负责标准 Markdown 题卡写入；`task_store.py` 负责任务快照和进程重启后的中断标记；`app.py` 只注册路由、页面和后台服务，不承载 Profile 细节。

## 4. 监听与任务生命周期

统一监听服务以周期扫描为可靠底线，可叠加文件系统事件但不能依赖事件不丢失。文件进入目录后先为 `pending`，至少连续两个检查周期的大小和 `mtime_ns` 不变，并可共享读取，才进入 `queued`。入队前和转换前各计算一次 SHA-256，防止检查窗口内文件继续写入。

任务状态：

```text
pending -> queued -> converting -> validating -> committing -> committed
                                             \-> failed
committing -> recycle_pending -> committed
```

输入路径、内容哈希和 Profile 组成活动任务去重键。同一指纹只能有一个活动任务。进程重启后，不能自动重放可能已调用外部 OCR 的 `converting` 及之后在途任务；这些任务标记为 `interrupted`，由用户明确重试。已提交但仅回收站失败的任务可以安全重试回收。

监听器必须排除输出目录、临时目录、隐藏目录、状态文件以及不支持的扩展名；自定义输入与输出目录重叠时也要通过规范化路径排除输出树，避免把新产物再次当成输入。

## 5. 三条处理链路

### 5.1 好题

一张图片进入 MinerU 图片识别，结果经过现有题卡规范化并生成一张独立 Markdown 题卡。好题路径不猜测把一张含多题图片拆成多题；检测到多题或质量门不通过时转为人工校对任务。

文件名以源文件名（去扩展名）为基础，并自动识别主题号追加后缀：`圆梦杯.png` → `圆梦杯第11题.md`。只从正文开头移除识别出的主题号标记；小题号、选项号和正文其他编号原样保留。无法可靠识别主题号时保留基础名并写入待校对告警。重名版本为 `圆梦杯第11题_2.md`、`圆梦杯第11题_3.md`。

### 5.2 好卷

一份试卷经过 MinerU 后，显式执行卷首语、页眉、页脚和页码等版面噪声清理，再使用现有题目边界和规范化链路提取全部题目。每题独立成卡，按源文件名加题号命名，并包装在一个版本目录中：

```text
圆梦杯/
  圆梦杯第1题.md
  圆梦杯第2题.md
圆梦杯_2/
  圆梦杯第1题.md
```

版本目录同时保留来源元数据、题目顺序、图片资源、输出清单和质量报告。清理规则必须是 Profile 的显式策略，不依赖通用切题偶然删除噪声。

### 5.3 好资料

书籍、讲义等资料经过 MinerU 后保留正文、题目、解析和原始顺序，按结构切为独立块卡。正文块、题目块、解析块全部进入同一资料版本目录；页码不写进正文，只写入 frontmatter 并在预览侧边展示。

块卡文件名保留源文件名并追加类型和序号，例如：

```text
高中数学教材第一章/
  高中数学教材第一章正文第1块.md
  高中数学教材第一章第1题.md
  高中数学教材第一章解析第1块.md
```

每张资料卡至少包含：

```yaml
qf_source_kind: good_material
source_document_id: ...
source_document_name: ...
source_version_id: ...
source_block_id: ...
source_block_index: 17
source_block_type: body | question | solution
source_page_start: 23
source_page_end: 24
source_order: 17
```

同一资料版本共享 `source_document_id` 与 `source_version_id`，保证整份资料可以按原顺序预览、重排和导出。

## 6. 事务、错误和安全边界

每个任务使用独立工作区，至少包含 `raw/`、`assets/`、`output/`、`manifest.json` 和 `report.json`。提交顺序固定为：验证输出清单和引用 → 计算输出哈希 → 在版本锁内分配序号 → 原子移动完整输出 → 发送源文件到系统回收站 → 写入 committed 版本登记。

任何中间失败都保留源文件，不留下半个公开版本。输出提交后回收站失败进入 `recycle_pending`。路径、扩展名、文件大小、真实格式、图片引用和 Markdown 解析继续复用现有安全边界；外部 OCR/LLM 凭据不写任务快照、版本登记或日志。

## 7. UI、Agent 和 CLI

设置页增加“自动导入工作站”区域，分别显示三个 Profile 的输入／输出目录、选择／恢复默认／打开目录按钮、监听开关、队列数量、运行任务、成功版本、失败任务和待回收任务，并提供暂停、重试转换、重试回收和打开输出目录操作。

桌面 GUI、交互式 CLI 与 Agent 共用上述服务和状态。Agent 工具至少覆盖读取／修改目录配置、启动／停止／暂停监听、列出任务与版本、重试失败转换、重试待回收源文件和预览版本输出；写操作沿用现有审批、快照和审计规则。

## 8. 验证计划

新增单元和集成测试覆盖：默认目录与自定义目录、目录外本地路径、稳定文件与占用文件、输入输出相同／不同、内容哈希去重、内容变化产生独立版本、并发序号锁、好题主题号与小题号、好卷噪声清理、好资料块类型／顺序／页码、输出失败源文件保留、系统回收站成功／失败／幂等重试、重启中断恢复、输出清单和引用完整性，以及既有手动导入／题库扫描／导出回归。

真实验证需记录完整命令、解释器路径和版本、输入文件路径、随机种子（如使用）、代码版本、任务 JSON、输出清单、报告和哈希；未执行的检查不得写成已通过。系统回收站测试应使用临时本地目录和可恢复样本，明确验证源文件进入回收站而非永久删除。

## 9. 明确取舍

- 采用统一监听器而非三个独立监听器，避免队列、稳定性、重试和版本语义分叉。
- 采用 Profile 而非重写 OCR 后端，保持现有 MinerU/Doc2X 和手动导入兼容。
- 采用系统回收站而非内部归档，满足用户确认的原地替换语义；因此恢复入口依赖 Windows 回收站，QuizForge 只记录回收状态。
- 采用永久保留的递增版本而非只保留最新结果，优先保证可对照、可回退和审计能力。
- 允许目录位于 `BANK_DIR` 外，但拒绝网络路径、越界符号链接和不可验证目录，平衡自定义能力与本地安全边界。
