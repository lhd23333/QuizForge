# QuizForge 商用演进路线设计

## 1. 目标与决策摘要

QuizForge 软件版继续以本地 Markdown 题库为唯一真源，在不破坏 Obsidian 可读性、离线使用和旧题兼容的前提下，逐步补齐教师常用的 Word 交付、结构化检索、预设标签、AI 题库治理和云端服务能力。

本轮确认的产品决策如下：

1. 云端不默认同步整套题库，只提供账号、授权、AI 和隔离编译服务；桌面软件在用户明确发起任务时上传最小必要材料。
2. 预设标签树只用于快速选择和组织普通标签。用户可跨层级、多选标签，也可继续手动输入标签；二者最终并行存入现有 frontmatter `tags` 字段。
3. 题目只保存用户实际勾选的标签，不自动写入全部祖先标签；检索父节点时，由预设树动态展开其全部后代标签，所以移动树节点不需要重写题目。
4. Word 导入保持现状：DOCX 先转 PDF，再进入现有 OCR／识别链；不新增 DOCX 直转 Markdown 导入路径。
5. Word 导出以可二次编辑为首要目标，直接由结构化题目生成 DOCX，不采用 PDF 转 Word。
6. AI 第一版只允许修改当前已登记题库；题库外的试卷目录只读扫描并生成建议，不执行改名或移动。
7. 云端第一阶段面向封闭测试规模，但 TeX 编译和 AI 等重任务必须脱离 Web worker，并具备持久状态、归属校验和资源隔离。

这些能力拆成五个可独立验收的子项目，依次实施：结构化搜索、预设标签树、Word 导出、AI 题库管家、桌面云服务。每个子项目单独形成实施计划和版本，不把五条线塞进一次大改动。

## 2. 结构化搜索

### 2.1 查询语义

题库首页继续使用现有 `q` 参数和单一搜索框。查询中出现受支持的 `字段:值` 时进入结构化模式；完全不含受支持字段时保留普通文本搜索，避免改变既有书写习惯。

第一版支持：

- `tag:函数`：搜索普通标签；若“函数”精确命中预设树节点的显示名或规范标签，同时匹配该节点及全部后代节点对应的标签。
- `content:"二次函数"`：只搜索题干 `body`。
- `solution:构造`：只搜索解析 `solution`。
- `source:期中考试`：只搜索题源 `source`。
- `type:选择题`：匹配规范题型。
- `difficulty:3`：匹配规范难度字符串。
- `starred:true`：匹配标星状态；接受 `true/false` 和 `1/0`。

多个条件默认 AND。带空格的值使用双引号；第一版不支持括号、OR、NOT、通配符或相似度搜索。现有侧栏标签、题型、难度、标星和文件夹筛选继续保留，并与搜索条件按 AND 叠加。

搜索范围始终是用户提交搜索时的当前题目视图，而不是自动退回全库：当前题库／浏览视图、当前文件夹（含该视图原本约定的后代范围）、“全部题目”状态以及已经生效的标签、题型、难度、标星等筛选共同组成基础集合，搜索只在这个基础集合内继续取交集。“当前显示范围”指该视图对应的完整逻辑结果集，不是无限滚动此刻已经加载到浏览器中的 30／60 张题卡；尚未加载的匹配题也必须能出现在搜索结果中。

搜索表单提交时必须保留当前范围相关的查询参数，清除搜索只删除 `q` 和搜索语法错误，不清除文件夹、标签、题型、难度、标星、排序或当前视图。用户随后切换文件夹或筛选项时，现有搜索条件继续作用于新的当前范围，直到显式清除搜索。

未知前缀按普通文本处理，防止数学内容中的冒号被误判；已识别字段的非法值或未闭合引号返回可读错误，页面保留原查询，不静默退回其他含义。普通文本搜索继续覆盖题干、解析、标签和题源，修正当前界面宣称可搜题源、实际未搜索 `source` 的不一致。

### 2.2 模块边界

新增纯逻辑查询模块，负责把原始字符串解析为不可变查询对象；它不读取 Flask 请求、不扫描题库，也不修改文件。`filestore.list_questions()` 只消费查询对象并执行过滤。页面路由负责把解析错误和原字符串传给模板。

预设标签树尚未启用时，`tag:` 只匹配普通标签；启用后由标签方案模块提供父节点到规范后代标签集合的解析接口。服务器版后续可以复用语法和测试，但用自己的 SQL 执行层，不复制软件版文件扫描实现。

### 2.3 验收边界

自动化覆盖普通搜索兼容、各字段、引号、多条件 AND、未知前缀、非法值、父节点展开，以及与现有筛选叠加；另锁定文件夹／全部题目范围、清除搜索只移除 `q`、搜索覆盖未加载题卡三项语义。真实页面验证查询参数在搜索提交、清除、排序、无限滚动、文件夹切换、筛选切换和返回原题位置时不丢失。

## 3. 预设标签树

### 3.1 存储模型

每个题库的自定义方案保存在 `.quizforge/tag-presets.json`。点目录已被题目扫描和目录树排除，配置可随 vault 迁移，又不会被识别为题目。文件采用带版本号的 JSON：

```json
{
  "schema_version": 1,
  "schemes": [
    {
      "id": "稳定方案ID",
      "name": "高中数学知识体系",
      "nodes": [
        {
          "id": "稳定节点ID",
          "label": "函数",
          "tag": "函数",
          "children": []
        }
      ]
    }
  ]
}
```

节点 ID 在改名、移动和排序后保持不变。每个节点都可勾选并映射到一个普通字符串标签；同一方案内规范标签不得重复，跨方案允许指向同一个普通标签。软件内置方案只读存放在发行资源中，用户修改前复制为题库自定义方案，升级不得覆盖个人方案。

### 3.2 选择和检索

题卡编辑、批量加标签和导入校对页可以打开多套标签树。用户能跨方案、跨层级勾选多个节点；勾选结果与手动输入标签合并、去重、保序后，仍写回题目已有的 `tags: [...]`。系统不记录“这个标签来自预设还是手动”，因此删除方案不会删除题目标签，手动输入与节点规范标签同名时也天然成为同一标签。

勾选父节点只保存父节点自己的规范标签；勾选子节点只保存子节点自己的规范标签。父节点筛选和 `tag:` 精确命中父节点时，查询集合为父节点自身标签加全部后代标签。树节点移动只改变未来的父级检索范围，不批量改写任何题目。

### 3.3 管理操作

方案管理支持创建、复制、改名和删除方案，以及节点新增、移动、排序、改显示名和改规范标签。改显示名、移动或排序只改方案文件；改规范标签属于题库批量变更，必须先显示受影响题目数和文件清单。

规范标签改为一个已存在标签时执行合并；删除节点默认只从方案中删除，不移除题目已有标签。批量改名／合并在应用前重新核对题目原始字节，任一外部修改或写入失败都拒绝或回滚整批，不能沿用当前逐文件更新后半途失败的弱语义。

## 4. Word 导出

### 4.1 范围

DOCX 导入不变，继续使用现有“Word → PDF → OCR／识别”路径及纯图片 DOCX 特例。本项目只新增 DOCX 导出。

DOCX 的目标是内容、公式、表格、图片和结构可继续编辑；PDF 继续是最终印刷版式的权威。第一版覆盖题库首页已有的普通题目列表、简单／标准试卷、双栏刷题和 16:9 横向课堂演示，以及“不含解析／题后解析／文末解析”三种解析模式；双栏和横向模式使用 Word 原生分节与分页表达，不承诺与 PDF 等价。

### 4.2 生成路径

新增独立 Word 语义渲染器，复用题目选择、题号、分区、解析模式、表格解析和图片布局意图，但不复用当前包含 raw LaTeX 的 PDF Markdown。渲染器生成 Pandoc Markdown，随后由随包 Pandoc 直接输出 DOCX。

公式交给 Pandoc 转为 Word OMML；图片先复制到独占工作目录并使用本地相对路径；Markdown／HTML 表格统一转为 Pandoc 可写入 DOCX 的表格结构。`reference.docx` 控制中文字体、标题、题号、页边距、表格、页眉页脚和解析样式。必要的后处理只修改 DOCX OOXML 中明确、可测试的分节、分页和图片尺寸，不从 PDF 反推版面，也不引入 Word COM 依赖。

导出接口增加 `docx` 格式，文件扩展名、MIME、下载名和许可证门控与现有导出统一。缺失 Pandoc、图片损坏或 DOCX 未生成时返回明确失败，不返回半成品。

### 4.3 验收边界

自动化检查生成命令、允许模式、公式／表格／图片输入、解析位置和失败清理。真实产物必须用 Word 或 WPS 打开，确认中文、可编辑公式、表格、图片、题号、分页、页眉页脚和三种解析模式；再用 Pandoc 回读 DOCX，核对核心文本和公式数量不丢失。

## 5. AI 题库管家

### 5.1 四层结构

1. 清单层由程序读取当前题库的目录、题目 ID、题源、标签、题型、哈希和 mtime。默认只外发目录名、题源和标签统计；只有用户明确选择时才加入题干摘要。
2. AI 层只返回符合固定 JSON schema 的建议，不拥有文件系统入口。
3. 审核层展示执行前后差异、影响数量、置信度和理由，用户逐项勾选并可修改目标。
4. 执行层重新校验路径、哈希和 mtime，在题库写锁下拒绝越界、保留目录、符号链接、重名覆盖和审核后外部修改，并写入可回滚操作记录。

第一版提供“整理文件夹”“治理标签”“为题目补标签”三类任务。允许的写操作包括题库内创建／改名／移动文件夹、移动题目、增删普通标签、标签改名／合并和预设树调整。题库外目录只能只读扫描并导出建议清单，不执行任何文件改名或移动。

操作日志和必要备份写入当前题库 `.quizforge/operations/<任务ID>/`，题目扫描自动忽略。应用建议前必须复验清单快照；回滚也必须确认目标文件未被后续外部修改，不能覆盖用户的新编辑。

### 5.2 模型与隐私

本地模式复用 OpenAI 兼容客户端，新增独立 `organize` 用途；未单独配置时可以显式回落当前 Markdown 识别模型。云端模式以后通过服务端口适配，业务层只消费结构化建议。

任务快照记录模型标识、输入字段摘要、用户最终批准项和结果，不保存明文密钥。界面在发送前列明将外发的字段和预计题目数；完整题干、解析、图片和外部目录内容均不得默认上传。

## 6. 桌面云服务

### 6.1 产品边界

复用 `quizbank-web/` 现有账号、管理员、HTTPS 和导出基础，但新增版本化桌面 API，不让桌面端调用网页表单路由。现有服务器题库与桌面本地题库保持独立，云服务不把本地 vault 导入服务器数据库。

桌面登录采用设备授权流程：客户端申请一次性代码并打开 HTTPS 授权页，用户在网页端登录确认；客户端轮询取得短期访问令牌和可撤销刷新令牌。刷新令牌在服务端只存哈希，在桌面端用现有本机加密边界保存。管理员可禁用账号、撤销设备并调整云编译／AI 额度。

离线许可证继续控制本地导出；账号权益控制云编译和云 AI。账号离线或云服务不可用时，本地题库阅读、整理和已获许可的本地能力不被锁死。

### 6.2 远程编译

桌面端使用现有可靠排版链生成带版本清单的 TeX ZIP，只上传本次 TeX、图片和必要资源，不上传题库。云端创建持久任务，独立编译 worker 在无网络、低权限、独占临时目录和 CPU／内存／时间限制下运行 XeLaTeX；必须禁用 shell escape，并限制文件读写范围。

Web worker 只处理鉴权、额度、上传、状态和下载，不直接编译。客户端轮询任务状态并下载 PDF；输入、日志和产物按明确 TTL 自动删除，日志不记录题目正文。每个任务的创建、查询、取消和下载均校验账号归属。

封闭测试阶段允许继续使用 SQLite，但任务领取必须通过数据库原子状态转换，由独立 worker 读取，不能继续依赖进程内字典。真实并发和存储压力达到迁移阈值后，再单独设计 PostgreSQL、对象存储或专用队列；不在第一阶段引入整套微服务。

### 6.3 现有路线冲突

`quizbank-web/docs/ROADMAP.md` 当前明确“不做 Redis、Celery 或 PostgreSQL 迁移”，这与新的长期商用云服务方向存在范围变化。第一阶段只新增持久任务表和独立 worker，不立即引入上述组件；进入扩容阶段前必须新增 ADR，明确 supersede 旧路线中与云任务扩容冲突的部分。

## 7. 实施顺序与发布策略

1. 先实现结构化搜索，建立纯逻辑查询接口和兼容语义。
2. 再实现预设标签树，并把父节点展开接入 `tag:` 和侧栏树筛选。
3. 单独实现 Word 导出及真实 DOCX 回归，不改 Word 导入。
4. 在标签与文件批量写入具备原子保护后，实现 AI 题库管家。
5. 最后扩展服务器端桌面 API、设备授权和隔离编译 worker，再接云端 AI。

每个阶段都按软件版规则完成源码验证、`DirectBundle` 原位同步和安装版验收；默认不生成 Setup。产生用户可感知能力时更新 PRODUCT、CHANGELOG 和 README；云服务改变部署或任务边界时同步 ARCHITECTURE、管理者手册和 ADR。

## 8. 非目标

- 不把 Word 导入改成 DOCX 直转 Markdown。
- 不用 PDF 转 Word，也不承诺 DOCX 与 PDF 像素级一致。
- 不把标签迁移为数据库 ID，不因预设树变化自动重写全部题目。
- 不允许 AI 绕过审核直接操作文件系统。
- 不在第一阶段同步完整本地题库、实现实时协作或一次性重构服务器版。
